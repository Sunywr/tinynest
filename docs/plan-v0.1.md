# TinyNest V0.1 实施计划：家庭财务核心账本

> - **产品**：TinyNest（小家）
> - **版本**：V0.1
> - **文档状态**：待实施基线（本文件为 V0.1 唯一权威计划）
> - **目标**：在 Phase 0 工程骨架上，交付可供家庭真实使用的第一版财务账本。
> - **设计原则**：账务准确优先于功能数量；所有自动化均可追溯、可撤销、不可重复入账。

---

## 1. V0.1 的目标与边界

V0.1 不再只是展示型 Demo，而是建立一套可真实记录家庭收支、信用工具、分期负债和投资交易的基础账务系统。

### 1.1 本版本必须交付

1. 日常收入、支出、账户转账、退款记录。
2. 自定义分类及项目归集，支持记账时快速创建项目。
3. 现金账户、证券账户、理财账户的建立与余额管理。
4. 信用卡、花呗、美团月付、抖音月付等信用工具及账单周期管理。
5. 信用账单汇总、还款记录和未还金额计算。
6. 分期合同、逐期计划、到期自动生成待处理还款事项。
7. 房贷、分期、保险等固定负债/付款义务，支持现金或信用工具支付。
8. 股票及理财产品的买入、卖出、费用、持仓成本、分红和收益计算。
9. 首页现金流、收支、负债到期情况、投资收益和家庭净资产概览。
10. PC Web 和 iPhone PWA 均可完成核心操作。

### 1.2 本版本明确不做

- 不接入银行、证券公司、支付宝、微信、花呗等第三方开放接口。
- 不自动读取邮箱账单或短信，不做自动对账导入。
- 不接入实时股票行情；证券和理财产品市值先由用户手动更新。
- 不自动发起真实扣款、信用卡还款或证券交易。
- 不做多币种、税务申报、复杂家庭预算、AI 财务顾问。
- 不做 App Store 上架或原生 iOS App。
- 不做多租户 SaaS。系统部署在用户自己的服务器，V0.1 只服务一个家庭账本。

上述功能可作为 V0.2 及以后版本的候选项，不得为了预留而提前引入不必要的微服务或复杂基础设施。

## 2. 沿用的工程与产品基线

以下内容继承 Phase 0，未经用户确认不改变：

| 项目 | 决定 |
|---|---|
| 产品名称 | TinyNest / 小家 |
| 视觉风格 | A · 奶油团子 |
| 图标 | 使用用户提供的原始糯米团子图，不改绘、不换图 |
| 前端 | Vue 3 + TypeScript + Vite |
| 后端 | Go API，模块化单体，不拆微服务 |
| 数据库 | SQLite，存放在后端服务器 |
| 前后端部署 | 两台不同服务器 |
| 入口 | 前端 Nginx HTTPS，同源 `/api/v1` 反向代理到后端私网地址 |
| 客户端 | PC Web + iPhone Safari 添加到主屏幕的 PWA |
| 时区 | Asia/Shanghai |
| 默认币种 | CNY（人民币） |

### 2.1 两台服务器的职责

**前端服务器 A**
- Nginx、HTTPS 证书、前端静态资源。
- 将 `/api/v1/*` 通过私网 TLS 转发到后端服务器 B。
- 不保存 SQLite 文件、数据库备份或后端密钥。

**后端服务器 B**
- Go API、定时任务、SQLite 数据库、备份文件。
- Go 服务只绑定本机或私网地址。
- SQLite 不通过公网、NFS 或前端服务器共享。
- 单实例写入；不得启动多个 API 实例同时写同一个 SQLite 文件。

### 2.2 数据库运行要求

- SQLite 启用 WAL、外键约束和合理的 `busy_timeout`。
- 重要业务操作必须在单个数据库事务中完成。
- 定时任务必须有唯一业务键，重复执行不能重复生成账务。
- 每日备份，并定期验证恢复。
- Service Worker 只缓存应用静态壳，不缓存 `/api` 响应和任何私人财务数据。

## 3. 账务内核：所有模块必须遵守的规则

这是 V0.1 最重要的设计。不要将“页面上的一笔记录”简单等同于“现金减少”。系统必须区分收入、消费、资产转移和负债偿还。

### 3.1 采用复式记账内核

所有已确认的业务事件最终写入统一的 `journal_entries` / `journal_lines` 分录账本。每笔分录借贷必须平衡。业务表负责表达用户操作和业务状态，分录负责表达资产、负债、收入、费用的变化。

基本分录示例：

| 场景 | 借方 | 贷方 |
|---|---|---|
| 现金支付日常支出 | 对应费用分类 | 现金账户 |
| 信用卡支付日常支出 | 对应费用分类 | 对应信用负债 |
| 收到工资 | 现金账户 | 工资收入 |
| 自有账户互转 | 转入账户 | 转出账户 |
| 信用卡还款 | 信用卡负债 | 现金账户 |
| 现金退款 | 现金账户 | 原支出冲减 |
| 退回信用卡 | 信用卡负债 | 原支出冲减 |
| 股票买入 | 股票持仓资产（含买入费用） | 证券资金账户 |
| 股票卖出 | 证券资金账户及/或处置损益 | 股票持仓资产 |
| 收到税后分红 | 现金账户；必要时记录税额 | 投资分红收入及税额对应科目 |
| 房贷还款 | 房贷本金负债、利息费用 | 现金账户或信用卡负债 |

**必须保证以下口径：**

- 信用卡消费在消费发生时计入支出；还信用卡时只减少信用卡负债，不再次计入支出。
- 自有账户转账不属于收入或支出。
- 股票/理财买入是资产转换，不属于日常消费。
- 股票/理财卖出本金不属于收入；已实现收益单独计算。
- 贷款还款中的本金部分减少负债，利息/手续费部分才是费用。
- 退款必须关联原交易，作为原支出的冲减，不得错误计入普通收入。
- 分期购买在购买时确认原始消费；后续分期付款只结清分期负债，利息/手续费按期确认费用。
- 自动生成的到期事项只能是“待支付”，不得自动标记为已支付。

### 3.2 金额、数量与精度

- 金额统一使用整数“分”存储（`amount_minor`），禁止使用浮点数保存人民币金额。
- API 金额以十进制字符串或整数分传输，前端展示时再格式化。
- 股票/基金份额使用定点整数保存，例如 `quantity_scaled`，明确 scale；价格也使用定点数。
- 费用计算必须在后端完成，前端只展示预览结果。
- 舍入规则统一为四舍五入（half-up），并记录计算前金额、费率、最低费用和最终费用。
- V0.1 默认仅 CNY；数据库字段仍保留 currency，避免以后迁移困难。

### 3.3 已确认账务的修改方式

- 草稿可以编辑、删除。
- 已入账记录不得物理删除。
- 已入账记录的纠错采用“冲正原分录 + 新建正确记录”，保留操作人、时间和原因。
- 退款、冲正、撤销、重新生成均保留关联 ID。
- 任何一笔业务操作和对应分录必须在同一个数据库事务中提交。

## 4. 分类、项目与日常记账

### 4.1 默认支出分类

首次初始化时创建以下可编辑分类：

- 饮食
- 零食
- 运动
- 服饰
- 交通
- 生活
- 家具
- 玩具
- 游戏
- 娱乐
- 教育
- 育儿
- 工作
- 旅行
- 住房
- 汽车

“转账”不作为支出分类，而是独立的业务类型，避免统计时把账户内部资金移动误认为消费。

分类采用两级结构：一级为上述大类，用户可在其下创建二级子分类，例如“饮食 / 早餐”“饮食 / 午餐”“育儿 / 奶粉”“育儿 / 尿不湿”。不允许无限层级，避免分类树过深。

可允许用户后续新增、改名、停用分类；已有交易保留原分类关联，不因分类停用而丢失历史数据。若某一级分类已有子分类，记账时既可选一级汇总，也可选具体子分类；统计时一级分类应自动汇总其子分类。

### 4.2 默认收入分类

- 工资
- 报销
- 红包
- 利息

另设“投资分红”专用收入来源，由投资模块生成，避免与普通利息混淆。分类可自定义。

### 4.3 记账字段

每笔普通交易至少包含：

- 交易类型：支出 / 收入 / 转账。
- 发生时间、金额、币种。
- 分类。
- 付款账户或收款账户。
- 支付工具：现金账户 / 信用工具。
- 项目（可选）。
- 家庭成员（可选）。
- 商户/对象（可选）。
- 备注（可选）。
- 创建时间、创建人、状态。
- 来源关联：退款、分期、负债还款、投资交易等业务 ID（如适用）。

记账表单要支持快速录入，常用分类、账户和项目优先展示；不能为了完整性让普通记账变成复杂表单。

一笔消费默认对应一个分类；对于一张小票包含多个类别的情况，允许展开“拆分明细”，将总金额拆成多行，每行选择子分类和金额。拆分行金额之和必须严格等于交易总额。项目可按拆分行指定，未拆分时在整笔交易上指定项目。拆分不是多次付款，不得重复减少账户余额。

### 4.4 项目管理

项目是跨分类的统计维度，不是新的账户或分类。

示例：
- 2026 年客厅装修
- 2026 年海南旅行
- 宝宝出生及育儿
- 家庭汽车购置

要求：
- 记账时可以搜索并选择已有项目。
- 记账时可以直接创建新项目，不必离开表单。
- 未拆分交易可直接关联一个项目；拆分交易允许每个拆分行分别关联项目，便于一张账单同时归集到不同项目。
- 项目支持名称、起止日期、说明、状态。
- 项目详情展示累计收入、累计支出、净额、交易明细和分类构成。
- 项目停用后仍可查看历史数据。

## 5. 账户体系

账户分为三类，信用工具和贷款负债另行建模，不混入现金资产账户。

### 5.1 现金账户

可创建多个，例如：
- 现金
- 工资卡/储蓄卡
- 家庭共同账户
- 微信零钱
- 支付宝余额

字段：账户名称、账户子类型、开户/归属成员、期初余额、当前余额、启用状态、备注。

### 5.2 股票账户

- 证券账户名称、券商、账户归属成员。
- 证券资金余额（可手动设置期初余额）。
- 关联交易费用规则。
- 持仓及资金流水。
- V0.1 不接券商接口，余额和交易由用户手工录入。

### 5.3 理财账户

- 理财账户名称、机构/平台、归属成员。
- 账户现金余额。
- 关联理财产品持仓、份额、成本和最新估值。
- V0.1 由用户手动更新净值/估值。

### 5.4 期初余额

建立账户时允许录入期初余额。期初余额通过“期初权益”科目入账，不得伪装成工资或其他收入。期初负债同理，计入期初负债和期初权益。

## 6. 信用工具与账单管理

### 6.1 支持的工具类型

- 信用卡
- 花呗
- 美团月付
- 抖音月付
- 其他自定义信用工具

每个工具作为独立负债账户，不能将多个平台的负债合并成一个余额。

### 6.2 配置字段

- 工具名称、类型、发卡机构/平台。
- 归属家庭成员。
- 信用额度（可选）。
- 账单周期开始日。
- 账单周期结束日。
- 还款日。
- 还款日相对账单结束日的月份偏移（当月/次月）。
- 启用状态。
- 备注。

日期规则必须处理 28/29/30/31 日及大小月。例如结束日为 31 日时，二月应按月末规则处理，不得产生无效日期。实际账单可允许人工修正开始日、结束日和还款日。

### 6.3 账单生成与计算

- 普通信用消费、信用退款、信用卡支付非信用负债、分期当期转入金额，都必须能归入对应账单周期。
- 到账单周期结束后生成账单汇总。
- 账单至少展示：周期起止日、应还金额、已还金额、剩余应还、还款日、状态、明细。
- 状态：未出账 / 已出账 / 部分还款 / 已还清 / 逾期。
- 账单金额由明细和分录汇总计算，不能让用户同时维护两个互相矛盾的余额。
- 允许录入银行/平台账单上的实际金额作为核对值；若与系统金额不同，展示差额和待核对状态，不覆盖系统流水。
- 支持提前还款和部分还款。
- 还款是现金账户到信用负债的结算，不是新支出。

### 6.4 信用额度

若配置了信用额度，展示已用额度、可用额度和使用率。额度未知时不显示百分比，不得按零额度计算。

## 7. 退款

退款作为独立业务对象，必须关联原始支出。

### 7.1 功能

- 全额退款。
- 部分退款，可多次退款。
- 记录退款日期、退款金额、退款去向（原信用工具/现金账户/其他现金账户）和备注。
- 原支出展示原始金额、累计退款、净支出、剩余可退金额。
- 累计退款不得超过原始交易金额；特殊补偿/额外赔付应作为独立收入记录，不伪装成退款。

### 7.2 退款处理规则

- 退款退回原信用工具：减少对应信用负债。
- 退款退回现金账户：增加该现金账户余额。
- 退款冲减原支出分类和原项目统计。
- 部分退款必须指定冲减原交易的哪个分类/项目拆分行；全额退款默认按原拆分行剩余金额全部冲减。
- 原始记录不删除，退款明细可追溯。
- 退款跨月时，当前月份现金流按实际退款日期统计；历史原始消费仍保留，累计项目净支出按原支出减累计退款计算。
- 分期订单退款需展示未到期计划影响；V0.1 允许用户确认后调整/取消未来期次，已经支付的期次通过退款记录处理，不得静默删除。

---

## 8. 分期付款

分期既可能由现金逐期支付，也可能通过信用卡/花呗等工具支付。

### 8.1 分期合同字段

- 合同名称/商户。
- 关联原始支出。
- 原始消费本金。
- 总手续费/利息（可为 0）。
- 分期期数。
- 首期日期、周期（月/自定义日期）。
- 每期本金、手续费、应付总额。
- 每期付款渠道：现金账户或指定信用工具；允许按期修改。
- 备注、合同状态。

### 8.2 期次计划

- 支持自动按月生成日期，也支持用户逐期修改日期和金额。
- 用户确认后，所有期次本金之和必须等于合同本金；手续费之和必须等于总手续费；每期应付金额等于本金加费用。
- 最后一期允许承担舍入差额。
- 期次状态：待支付 / 部分支付 / 已支付 / 已逾期 / 已取消。
- 每期付款记录保存实际付款日期、实际金额、付款渠道和关联分录。

### 8.3 账务规则

- 创建分期时，原始消费本金计入消费；同时建立分期本金负债。
- 每期现金支付：减少分期本金负债、确认当期手续费/利息费用、减少现金账户。
- 每期信用支付：减少分期本金负债、确认当期手续费/利息费用、增加对应信用工具负债。
- 如果已有信用卡消费转为分期，必须通过专门的“转分期”操作，把相应金额从信用卡负债重分类到分期负债，禁止同时保留两份本金。
- 到期自动生成待处理事项；只有用户确认实际支付后才入账。
- 定时任务使用 `contract_id + installment_no` 作为幂等键，重复执行不产生重复期次或重复交易。

## 9. 其他固定负债与付款义务

支持：
- 房贷
- 其他贷款
- 分期合同
- 保险缴费
- 其他固定付款义务

### 9.1 负债合同字段

- 名称、类型、归属成员。
- 合同总额、初始本金、当前未偿本金（适用时）。
- 开始日期、结束日期、周期。
- 还款/缴费日。
- 期次计划。
- 每期本金、利息、手续费、保费/服务费。
- 默认支付方式。
- 备注、附件预留字段。

### 9.2 不同负债的处理

- 房贷/贷款：本金部分减少贷款负债，利息部分计入支出。
- 分期：本金减少分期负债，手续费/利息计入支出。
- 保险：保费属于保险费用；未支付期次作为待缴义务展示，不虚构长期贷款本金。
- 其他合同：创建时选择其本金/费用拆分规则。

V0.1 优先支持手工录入每期拆分金额和固定周期自动生成。等额本息/等额本金计算器可列为 V0.1.x 或 V0.2，不得未经校验直接用估算金额冲减真实本金。

### 9.3 使用信用卡支付非信用负债

每笔负债付款均允许选择：
- 现金账户；
- 信用卡/花呗等信用工具。

若使用信用工具：
- 原贷款本金按实际本金部分减少；
- 对应信用工具负债增加实际刷卡金额；
- 利息/保费仍按其业务性质计入费用；
- 后续偿还信用卡时只结算信用卡负债，不重复记房贷/保险费用。

### 9.4 到期事项

每日定时任务生成未来计划的待处理付款事项；首页展示所选日期范围内应付、已付、逾期金额。未确认付款不得改变账户余额和负债余额。

## 10. 股票与理财投资

### 10.1 投资资产类型

- 股票
- 场内基金/ETF（作为可选证券类型）
- 银行/平台理财产品
- 其他自定义投资产品

V0.1 不接实时行情；当前价格、净值由用户手动更新，并记录估值日期。

### 10.2 交易类型

- 建仓：首次买入，系统根据交易前持仓自动识别。
- 加仓：已有持仓继续买入。
- 减仓：卖出部分份额。
- 清仓：卖出全部剩余份额。
- 分红：记录税前金额、红利税（可选）、税后金额和到账账户。

建仓/加仓/减仓/清仓是用户界面上的交易标签；底层统一使用买入/卖出数量和交易前后持仓计算，避免人工选择错误。

### 10.3 买卖字段

- 投资账户、资产代码/名称、市场/产品类型。
- 交易日期、方向、数量/份额、成交价格。
- 成交金额。
- 佣金、印花税、过户费、其他费用。
- 费用计算规则版本、自动计算值、用户修改值。
- 实际资金账户、备注。

### 10.4 费率规则

每个证券账户允许配置费用模板：
- 佣金费率。
- 佣金最低收费。
- 印花税费率及适用方向。
- 过户费率及适用市场。
- 其他费用规则。

要求：
- 自动计算费用，展示计算明细。
- 用户可以在单笔交易中修改最终费用。
- 保存费率快照，未来费率调整不能改变历史交易。
- 费率由用户根据实际券商交割单配置；系统提供字段和可编辑默认值，不把示例费率当成真实券商费率。
- 买入费用计入持仓成本；卖出费用从卖出净收入中扣除。

### 10.5 持仓成本和收益

V0.1 采用**移动加权平均成本法**，并在帮助说明中明确：
- 买入后更新持仓数量和单位成本。
- 卖出时按卖出前平均成本结转对应成本。
- 已实现收益 = 卖出净收入 - 卖出部分的结转成本。
- 未实现收益 = 当前估值 - 当前剩余持仓成本。
- 净分红 = 税前分红 - 用户填写的红利税。
- 投资总收益 = 已实现收益 + 未实现收益 + 累计净分红。
- 投资收益率参考值 = 投资总收益 / 历史累计买入成本（含买入费用）。

首页必须同时展示收益金额和收益率，并注明估值日期及收益率口径。V0.1 不提供 IRR/XIRR，不把该收益率称为年化收益率。

### 10.6 分红

- 记录除权/到账日期、资产、税前分红、红利税（可选）、税后金额、到账账户。
- 税额可填 0 或留空；留空代表未知，不得默认认定免税。
- 分红计入投资收益，不计入普通工资/红包收入分类。
- 现金分红可进入证券资金账户或家庭现金账户，按实际到账账户入账。

### 10.7 理财产品

- 支持买入、赎回、份额、净值、手续费。
- 支持手动录入最新净值和估值日期。
- 赎回时按移动加权平均成本计算已实现收益。
- 对没有份额概念的产品，允许使用金额份额模式，但必须明确单位定义。

## 11. 首页与统计口径

首页日期范围默认自然月，支持自定义起止日期。可保存用户上次选择。所有统计卡片必须标明统计周期。

### 11.1 首页首屏指标

1. **本期收入**：按收入发生日期统计。
2. **本期支出**：按消费发生日期统计，退款冲减原分类净支出。
3. **本期结余**：本期收入减本期支出。
4. **实际现金净流量**：现金/银行等资产账户实际流入减实际流出；信用卡消费不会提前减少现金，信用卡还款时才发生现金流出。
5. **本期应还负债**：所选日期范围内信用账单、贷款、分期、保险等应付金额。
6. **投资总收益**：已实现收益 + 未实现收益 + 净分红，显示估值日期。
7. **家庭净资产**：现金类资产 + 投资估值 - 信用负债 - 贷款等未偿负债。

### 11.2 其他建议关注的信息

- 未来 7 天 / 30 天待还款和待缴费。
- 已逾期账单/期次。
- 各信用工具本期应还、已还、剩余应还、额度使用率。
- 本期支出分类 Top N。
- 项目累计净支出/收入。
- 家庭现金余额和各账户余额。
- 投资账户持仓市值、成本、已实现/未实现收益。
- 本年累计投资分红及税额。
- 资产负债构成变化。

### 11.3 必须区分的三套口径

| 口径 | 统计方式 | 示例 |
|---|---|---|
| 收支 | 交易/业务发生日期 | 信用卡买菜当天计入支出 |
| 现金流 | 现金资产账户实际收付日期 | 信用卡消费当天不减少现金，还款日才减少现金 |
| 负债到期 | 合同/账单约定应付日期 | 信用卡账单、房贷、分期按还款日统计 |

不得将三套口径混成一个“本月支出”数字。

## 13. 数据库实体建议

AI Agent 应先提交 ER 图和迁移脚本，再实现 API。以下为建议实体，字段可根据实际代码规范细化。

### 13.1 家庭与基础资料

- `users`：登录用户。
- `households`：家庭账本。
- `household_members`：家庭成员档案及交易归属。
- `categories`：收入/支出两级分类，含 `parent_id`。
- `projects`：项目归集。
- `transaction_splits`：交易金额拆分行，保存分类、项目和拆分金额。
- `audit_logs`：关键操作审计。

V0.1 可先采用单家庭、单管理员登录；成员档案用于标注交易归属。完整邀请注册和细粒度权限留待后续。

### 13.2 账户与账务内核

- `accounts`：现金、证券、理财、信用负债等用户可见账户。
- `ledger_accounts`：复式记账科目。
- `journal_entries`：业务分录头。
- `journal_lines`：借贷分录行。
- `transactions`：日常收入/支出/转账业务记录。
- `transaction_splits`：一笔交易的分类/项目拆分；未拆分交易也以一条拆分行保存。
- `refunds`：退款及原交易关联。
- `account_opening_balances`：期初余额业务记录。

### 13.3 信用与账单

- `credit_instruments`：信用卡/花呗等配置。
- `billing_cycle_rules`：账单周期规则。
- `credit_statements`：实际账单周期和账单汇总。
- `credit_statement_items`：账单明细关联。
- `credit_payments`：还款记录。

### 13.4 分期和固定负债

- `installment_contracts`：分期合同。
- `installment_schedule_items`：分期期次。
- `debt_contracts`：房贷/贷款/保险等合同。
- `debt_schedule_items`：固定负债期次。
- `debt_payments`：实际付款记录。

### 13.5 投资

- `investment_assets`：股票、ETF、理财产品主数据。
- `investment_trades`：买卖交易。
- `investment_fee_rules`：账户费率规则。
- `investment_dividends`：分红记录。
- `investment_valuations`：手工估值历史。
- `investment_positions`：持仓计算结果/可重建投影，不作为唯一事实来源。

### 13.6 通用要求

- 所有业务数据带 `household_id`。
- 所有时间保存明确时区语义，数据库建议 UTC 存储、展示使用 Asia/Shanghai。
- 业务表有 `created_at`、`updated_at`、必要时 `created_by`。
- 金额使用整数分；数量/价格使用定点数。
- 关键关联使用外键和索引。
- 账务分录不可直接修改，使用冲正。
- 迁移脚本可重复检查、按版本顺序执行；禁止启动时无条件重建数据库。

## 16. 必须覆盖的验收用例

以下用例应自动化测试，不能只靠人工点击。

### 16.1 普通收支与账户

1. 现金账户期初余额 10,000 元，记录 100 元饮食支出，余额为 9,900 元。
2. 记录工资收入 8,000 元，收入统计增加 8,000 元。
3. 现金账户 A 转 1,000 元到账户 B，家庭资产总额不变，收入和支出不变。
4. 将 500 元支出归入“装修项目”，项目累计支出增加 500 元。

### 16.2 信用卡和退款

5. 信用卡消费 1,000 元，费用增加 1,000 元，现金余额不变，信用负债增加 1,000 元。
6. 还信用卡 600 元，现金减少 600 元，信用负债减少 600 元，支出统计不再增加。
7. 对原消费退款 300 元至信用卡，原交易净支出变为 700 元，信用负债减少 300 元。
8. 同一原交易再次退款时，累计退款不得超过原金额。
9. 账单周期跨月、月底 28/29/30/31 日时，起止日和还款日均正确。
10. 信用卡支付 2,000 元房贷，其中本金 1,500 元、利息 500 元：房贷负债减少 1,500 元，利息支出增加 500 元，信用卡负债增加 2,000 元，现金不变。

### 16.3 分期和固定负债

11. 创建本金 3,000 元、手续费 90 元、3 期分期；期次本金合计 3,000 元、手续费合计 90 元。
12. 到期任务运行两次，只生成一条待支付期次。
13. 确认现金支付一期 1,030 元，现金减少 1,030 元，分期本金减少对应本金，费用增加对应手续费。
14. 使用信用卡支付一期，现金不变，信用卡负债增加当期付款金额，分期负债按本金减少。
15. 贷款还款部分付款后，未支付部分仍保持待支付/部分支付状态。
16. 分期提前结清后，未来期次取消或调整，并保留历史付款记录。
17. 分期退款后，已付款期次不删除，未到期计划按用户确认结果调整。

### 16.4 投资

18. 买入 100 股，成交价 10 元，买入费用 5 元，持仓成本为 1,005 元。
19. 再买入 100 股，成交价 12 元，费用 5 元，持仓数量 200 股，总成本 2,210 元，移动平均成本 11.05 元/股。
20. 以 13 元卖出 50 股，卖出费用 5 元，已实现收益按卖出净收入减去 50 股平均成本计算。
21. 清仓后持仓数量和剩余成本为零，历史已实现收益保留。
22. 记录税前分红 100 元、红利税 10 元，净分红为 90 元；税额为空时显示“未填写”，不伪装成免税。
23. 手动更新估值后，未实现收益变化，但历史交易和买入成本不变。

### 16.5 首页与一致性

24. 信用消费、信用还款、退款、投资买卖分别发生在不同日期，首页收支、现金流、负债和投资收益按各自口径统计。
25. 自定义日期范围从当月 5 日到次月 4 日，所有模块使用相同的起止日期边界。
26. 任意一笔已入账交易冲正后，原分录和冲正分录均保留，余额恢复正确。
27. 任意业务发生数据库错误时，业务记录和分录必须同时回滚。
28. 备份恢复后，账户余额、信用负债、分期计划、投资持仓和首页汇总完全一致。
29. 一笔拆分交易的拆分行金额之和必须等于总金额；部分退款只能冲减指定拆分行的剩余可退金额。

## 17. 非功能要求与质量门禁

### 17.1 安全

- 密码使用 Argon2id 或同等级安全哈希，不得明文存储。
- Cookie 使用 HttpOnly、Secure、SameSite；写操作做好 CSRF 防护。
- 后端对所有资源校验 household 范围，不能只依赖前端隐藏按钮。
- API 错误不得泄露 SQL、路径、密钥或完整堆栈。
- 数据库文件和备份限制系统权限；备份建议加密并异地保存。
- 日志禁止输出密码、会话令牌、完整敏感账单内容。

### 17.2 可靠性

- 账务 API 支持幂等键。
- 定时任务可重复执行，失败可重试。
- 分录借贷不平衡时拒绝提交。
- 所有汇总都能从业务明细/分录重建。
- 数据库迁移有版本号、备份和回滚/恢复说明。

### 17.3 测试

- Go：单元测试、API 集成测试、数据库迁移测试。
- 前端：表单校验、金额格式化、日期边界、关键交互测试。
- 端到端：普通收支、信用账单、分期、退款、负债、投资。
- 视觉：PC 1440px、平板 768px、iPhone 390px。
- 性能：单家庭常规数据量下首页汇总和流水分页应保持流畅；复杂统计优先使用合适索引和可重建汇总，不得牺牲账务准确性。

### 17.4 发布门禁

以下任一条件未满足，不得标记 V0.1 完成：
- 核心分录测试全部通过。
- 所有关键金额使用定点/整数计算。
- 退款、信用还款、分期和投资没有重复记账。
- 首页三套统计口径通过测试。
- 备份恢复演练成功。
- PC 与 iPhone PWA 核心操作实测通过。
- 所有未完成项和已知限制写入发布说明。

## 18. 需要用户最终确认、Agent 不得擅自决定的事项

实现前先形成一页“默认值确认表”，以下问题可以先按建议值实现原型，但涉及真实账务口径的部分必须在正式入账前确认：

1. **家庭成员**：V0.1 是否只由一个管理员登录，其他家庭成员先作为交易归属档案？建议先采用此方式。
2. **现金账户范围**：是否把银行卡、微信余额、支付宝余额都统一归入现金类账户？建议支持多个现金账户及子类型。
3. **信用账单周期**：各平台按用户录入的起止日和还款日计算，允许单期人工修正。建议采用。
4. **分期购买确认时点**：创建分期时一次性确认完整消费，后续按期结算负债。建议采用。
5. **分期手续费**：按期分摊并计入对应月份费用；允许用户指定每期实际费用。建议采用。
6. **投资成本算法**：V0.1 使用移动加权平均成本法。建议采用；若以后需要与券商交割单逐笔税务口径一致，再扩展 FIFO。
7. **投资估值**：V0.1 先手动输入价格/净值，实时行情接口以后再接。建议采用。
8. **房贷/贷款计划**：V0.1 先支持录入每期本金、利息和日期；等额本息/等额本金自动测算是否纳入 V0.1.x。建议先不自动推断银行实际还款拆分。
9. **投资收益率**：先展示总收益金额及“总收益/历史累计买入成本”的参考收益率，不称年化收益率。建议采用。
10. **退款跨月**：当月现金流按实际退款日，项目累计净支出按原交易减累计退款。建议采用。

Agent 必须将未确认项标记为 `待确认`，不得用虚构默认值写入真实账务。
