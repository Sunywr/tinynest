## 2. FIX-01 · 保护首次初始化 `/api/v1/setup`（P1-01）

- **根因**：`handleSetup` 对所有人开放，空库时任意调用者可创建 `role='admin'`；初始化后 `COUNT(*)>0` 才返回 409，等于「谁先抢到谁是管理员」。`RemoteAddr == 127.0.0.1` 不可作为安全依据（Nginx 反代让公网请求看起来像本机）。
- **RED（修复前失败输出）**：
  - 不带任何凭据 `POST /api/v1/setup` → **201**，成功创建 admin 与家庭（应 401/403）。
  - 未配置 `TINYNEST_SETUP_TOKEN` 的进程 `POST /api/v1/setup` → **201**（应 fail closed）。
  - 失败用例：`TestSetupRequiresBootstrapToken`、`TestSetupDisabledWithoutConfiguredToken`、`TestSetupConcurrentBootstrapOnlyOneSucceeds`。
- **修复文件:行号**：
  - `apps/api/internal/api/setup.go:44` 定义 `X-Setup-Token` 头；`:48` `constantTimeTokenEqual`（SHA-256 digest + `crypto/subtle.ConstantTimeCompare`，常量时间比较，不泄露长度/内容）。
  - `apps/api/internal/api/setup.go:54-66` `handleSetup`：token 为空 → `403 setup_disabled`；token 不匹配 → `401 unauthorized`。
  - `apps/api/internal/api/setup.go:89-90` `setupMu` 串行化；`:95-121` `INSERT ... WHERE NOT EXISTS` 条件插入 + `RowsAffected()==0` → `409 conflict`；`:113` 唯一 `role='admin'`。
  - `apps/api/internal/api/helpers.go:47-68` `Options.SetupToken` 显式配置；`apps/api/cmd/server/main.go:81-88` 组合根读取 `TINYNEST_SETUP_TOKEN`，空库未配置时打印**不含令牌值**的 warn。
  - `apps/api/.env.example`、`docs/deployment.md:37`、`apps/web/src/services/api.ts`（`api.setup` 增加 `setup_token` 参数）、`apps/web/src/App.vue`（初始化表单增加一次性令牌输入，提交后清空、不存浏览器）。
  - `apps/api/internal/api/api_test.go`：`newTestServer` 注入 `Options{SetupToken: testSetupToken}`；测试名 `TestSetupIsSingleUseAndRequiresAuth` 改为 `TestSetupIsSingleUseAndSessionAuthEnforced` 并补齐「无 token 被拒 / 重复 setup 409 / 未登录 401 / 错误 CSRF 403」（修复 P2-09）。
- **GREEN**：4 个 setup 相关测试全部 PASS；真实二进制隔离演练中「无 token → 401」「带 token → 201」「二次 → 409」端到端 PASS。

## 3. FIX-02 · 全路径家庭数据隔离（P1-02）

- **根因**：`db.Balance` / `db.Aggregate` / `db.Cashflow` 的 SQL 只按科目与日期过滤，没有 `household_id`，等于全库汇总；`handleGenerateDueItems` 扫全表 `installment_schedule_items` / `debt_schedule_items`，且 `biz_key` 全局唯一，导致 A 家庭抢占 B 家庭的到期事项。
- **RED（修复前失败输出）**：两家庭并存时，两家的 income 均为 `1500000`、expense 均为 `90000`、cashflow 均为 `2010000`、net worth 均为 `1710000`（全库汇总值）；`schedule/generate` 返回 A generated `2`、B generated `0`，B 的 `source_id` 为空。
- **修复文件:行号**：
  - `apps/api/internal/db/db.go:246` `Balance(ctx,q,householdID,accountCode)`、`:261` `Aggregate(ctx,q,householdID,pattern,from,to)`、`:279` `Cashflow(ctx,q,householdID,from,to)`；三者均 `JOIN journal_entries e` 并下推 `e.household_id = ?`（`:251`、`:267`、`:287`）。
  - `apps/api/internal/api/dashboard.go:39,46,53,58,63,110` 全部调用点传入 `p.HouseholdID`。
  - `apps/api/internal/api/setup.go:396,477`、`apps/api/internal/api/credit.go:165` 的 `db.Balance` 调用补 `p.HouseholdID`。
  - `apps/api/internal/api/credit.go:518-560` `handleGenerateDueItems`：`JOIN installment_contracts c` / `debt_contracts c` 并 `WHERE c.household_id = ?`（`:533`），仅扫描本家庭期次；`:555` `bizKey := p.HouseholdID + ":" + src.kind + ":" + v.id` 改为 household scoped。
- **GREEN**：`TestHouseholdIsolation`、`TestHouseholdIsolationOnDetailEndpoints` PASS；两家庭统计与到期事项不再串账。

  - `apps/api/internal/api/setup.go:446` 期初余额 `ledger.Context{OccurredOn: a.businessDate()}`；`apps/api/internal/api/transactions.go:335` 冲正 `orig.Reverse(revID, a.businessDate())`。

- **GREEN**：`TestBusinessDateOpeningBalanceBoundaries`（UTC 00:01 / 16:00 / 23:59、月末、闰日、跨年 6 个子用例）、`TestBusinessDateReversalUsesShanghaiDay`、`TestBusinessDateDueItemsAndDefaultPeriod` 全部 PASS。

## 5. FIX-04 · 生产会话 Cookie `Secure`（P1-04）

- **根因**：`Secure: r.TLS != nil`；A 机 Nginx 终止 TLS 后以 `proxy_pass http://127.0.0.1:8787` 明文转发，Go 侧 `r.TLS` 恒为 nil。同时若直接采信客户端 `X-Forwarded-Proto`，又会被伪造头绕过。
- **RED（修复前失败输出）**：显式配置 `CookieSecure: true` 的进程登录后 `Set-Cookie` **无 `Secure`**；可信代理 + `X-Forwarded-Proto: https` 场景同样无 `Secure`。
- **修复文件:行号**：
  - `apps/api/internal/api/helpers.go:119` `parseTrustedProxies`（只接受显式 IP/CIDR，非法项忽略）、`:139` `trustedContains`、`:150` `remoteIP`、`:164` `clientIP`、`:183` `secureCookie`（**不依赖 `r.TLS`**，仅对可信代理来源采信 `X-Forwarded-Proto`）。
  - `apps/api/internal/api/setup.go:182` 登录 Cookie `Secure: a.secureCookie(r)`；`:204` 登出 Cookie 同源。
  - `apps/api/cmd/server/main.go:94-101` `TINYNEST_COOKIE_SECURE` 必须显式为 `true`/`false`，缺失或非法直接 `os.Exit(1)`；`:104-107` 非 loopback 监听且关闭 Secure 时打 warn。
  - `deploy/backend/tinynest-api.service.example`、`apps/api/.env.example`、`docs/security.md`、`docs/deployment.md` 同步。
- **GREEN**：`TestSessionCookieSecureInProductionProxy`、`...CanBeDisabledForLocalDev`、`...HonorsTrustedProxyForwardedProto`、`...IgnoresUntrustedForwardedProto` 全部 PASS；真实二进制本地演练确认 `TINYNEST_COOKIE_SECURE=false` 时 Cookie 不含 `Secure`。

## 6. FIX-05 · 登录失败限流（P1-05）

- **根因**：`handleLogin` 只校验用户名/口令与 Argon2id，无失败计数、无延迟、无锁定，可无限在线猜口令。
- **RED（修复前失败输出）**：连续失败全部返回 `401`，从不返回 `429`；20 个并发失败请求**全部 401、无 429**。首次实现后并发用例仍 FAIL，定位到 `allow()` 与 `failure()` 之间的 **TOCTOU 窗口**（所有并发请求在锁生效前都通过了 allow）。
- **修复文件:行号**：
  - `apps/api/internal/api/login_limiter.go`（新增）：`:15` 默认阈值 5 次 / 5 分钟窗口 / 60 秒有界冷却、IP 全局桶阈值 ×3；`:31` `loginLimiter`（`sync.Mutex` + principal/IP 两级 bucket）；`:69` `allow`、`:88` `failure`（返回 `(blocked, retry)`，在 mutex 内先检查已锁 bucket，消除 TOCTOU）、`:118` `reset`、`:138` `prune`（有界内存）、`:154` `limiterDigest`（审计只存摘要）、`:159` `retryAfterSeconds`。
  - `apps/api/internal/api/setup.go:144-146` 前置检查返回 `429 rate_limited` + `Retry-After`；`:154-156` 失败分支若已锁也返回 429；`:164` 登录成功 `reset`。
  - `apps/api/cmd/server/main.go:143-145` 环境变量 `TINYNEST_LOGIN_MAX_FAILURES` / `...WINDOW_SECONDS` / `...LOCKOUT_SECONDS`（非法值回落到保守默认，非密钥）。
  - 审计日志只含 `source_ip` 与 `principal_digest`，不含密码、session token、原始用户名。
- **GREEN**：`TestLoginFailureRateLimit`（连续失败 → 429、冷却后成功）、`TestLoginRateLimitScopeIsolation`（不同 IP/账号隔离、不泄露用户名存在性）、`TestLoginRateLimitConcurrentAndAuditSafe`（并发出现 429、审计不含敏感值）全部 PASS。
- **UNVERIFIED**：`go test -race ./...` 两次失败——`-race requires cgo` → `cgo: C compiler "gcc" not found`。并发行为由上述两个并发测试覆盖，**未伪造通过**。
