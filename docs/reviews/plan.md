# TinyNest 家庭混合记账审查与优化计划

审查基线为 `main` 的 `c014eeb`。家庭成员可以每天手记，也可以月底一次导入账单。验收以真实交易和账户变化为单位。例如同一笔 48 元午餐分别出现在手记、微信和信用卡账单中，已确认的三条来源应指向同一笔 48 元支出。同日同额且使用另一张卡的消费，应单独保留。

## 已实现

- **导入入口**位于首页，沿用信用卡邮件同步。支持多选 CSV、TSV、TXT、XLS 和 XLSX，识别支付宝、微信支付和常见银行卡表头。CSV 支持 UTF-8 和 GB18030。无法识别模板时可以选工作表、表头、列和金额正负规则，再查看预览。各发卡行具体模板覆盖尚待脱敏实单确认。
- **账户与成员**分别保存账单来源、账单账户标识、归属成员、上传账号、原始付款方式和实际资金账户。用户可按账单账户与付款方式记住绑卡关系。遇到同尾号或缺少付款方式时，由用户选择实际账户。
- **去重**按家庭、来源、账单账户、成员和稳定交易编号识别重叠导出。缺少编号时按文件指纹、工作表和行序识别原文件重传，同文件的同额重复行分别保留。横跨文件的模糊重复会通过账本候选提示复核。
- **核对**先按账本的资金账户、金额、方向、币种和交易日前后三天找候选。单一候选且共享长编号一致，或商户及交易日期均吻合时可自动关联。其他候选可手动关联或确认为另一笔。关联保留手记内容，只写来源和审计记录。新增流水与明细状态一同提交，重试读取已提交结果。
- **资金流**识别退款、信用卡还款与划转，允许按金额和相关账户关联已记记录。可从预览带入退款或还款表单，操作后回到自然月核对列表，通过候选确认关联。待确认性质、非人民币、混合支付或分期明细默认留给人工处理。
- **信用账单**只取得浦发应还总额时，记录银行侧金额供核对。费用暂记使用明确的本期新增金额。信用账单列表展示应还、已还、银行金额、差额与暂记。历史自动暂记目标与银行应还相同的账期显示复核提示，历史分录等用户确认账务口径后再走冲正。
- **中断恢复**导入明细和处理结果保存于 SQLite 或 MySQL。统一入口批量确认时逐项提交，刷新后以账本状态恢复。信用卡邮件的旧后台任务遇到同卡并发时提示冲突，独立于统一入口的持久化明细。

## 接口与数据

`/api/v1/statement-imports` 接受标准化明细并分页返回已保存记录。`/{id}/matches` 列出可核对的账本候选，`PUT /{id}` 保存账户选择、关联、入账或暂缓状态。首页使用 `/pending-count` 显示待核对数量。源文件解析在浏览器内完成，数据库保存标准化明细，不保存原文件。现有账本仍通过原有交易、退款和还款接口写入复式分录。

## 本地证据

Go 回归覆盖手记、微信和绑卡信用账单指向同一流水、第二张卡同日同额独立消费、重复上传、无编号同文件重复行、存疑记录与撤销关联。信用账单回归覆盖应还总额保留为银行核对数据及补录明细后的账本应还。调度回归原先因冻结时钟签发的 Cookie 在真实客户端时钟下被丢弃，采用等长的相对 Cookie 有效期后复测通过。

Go 全量测试、vet、构建、依赖一致性检查、前端类型检查、生产构建及品牌哈希通过。SQLite 从审查基线的迁移版本 19 升到 20 后，原有余额和分录合计一致。重复迁移、重启、备份恢复、外键和借贷平衡检查通过。

浏览器场景使用隔离 Go API 与 SQLite 验证微信 CSV 识别、重复上传和回到核对页。全量 Chromium 首轮有效回归 86 项通过，首页测试因仍查找预算占位提示失败，串行的系统邮件场景跳过。更新首页断言后，包含该两项在内的六个定向用例均通过。真实银行导出覆盖、生产 MySQL、iPhone 实机和真实账期的自动匹配准确率均为 `UNVERIFIED`。
