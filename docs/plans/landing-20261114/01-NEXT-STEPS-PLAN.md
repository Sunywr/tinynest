## 0. 工作原则与首轮代码核验

- 先执行 `git status --short`、`git branch -avv`、`git fetch --all --prune`、`git rev-parse HEAD`、`git log -12 --oneline --decorate`；核实当前 main、最近推送的功能分支以及 CI 状态。若网络失败，记录 `UNVERIFIED`，不要猜最新提交。
- 阅读 `AGENTS.md`、`README.md`、`docs/DEVELOPMENT.md`、现有前端路由/登录组件/布局组件、`apps/api` 的 setup/login 路由、PWA SW/manifest、Nginx 与部署文件；按实际源码路径调整下述方案。
- 基于最新且干净的 main 创建 `feature/tinynest-public-landing-motion`（或新 worktree）。保护所有未提交修改；不得 `reset --hard`、`clean -fd`、强推或直接合并。
- 输出 `docs/reviews/current-progress.md`：最新 commit SHA、Phase0/V0.1/V0.1.1/V0.1.2 实际状态、已实现的 API/页面/测试、CI 证据及未完成项目。只有真实实现/测试才能标 PASS。
- 生产数据库属于不可触碰资产。本轮默认**不需要修改财务表或数据**，若改动确实涉及迁移，必须提交隔离库演练、备份与回滚/恢复方案，并等待明确授权再应用到生产。

## 1. P0：生产初始化入口安全收口

### 1.1 视觉/路由

- 从公开页、登录组件、导航、PWA 离线页面等所有用户可见位置移除「初始化」「创建管理员」页签、链接、文案、步骤入口；避免只是 `display:none`、仅按 CSS 隐藏。
- 刷新、深链接、后退、旧 PWA 缓存页面都不能显示公开初始化表单；清理遗留公开路由或将其安全重定向。
- `setup` 不属于普通注册；无公开注册入口。生产管理员已存在，普通访客只能登录。

### 1.2 Go API（必须代码审计，禁止仅做 UI）

- 审核 `/api/v1/setup` 的当前实现及数据表初始化状态。已有管理员/家庭时，任何请求均不得新增/覆盖管理员（可保持现有 409，或安全禁用公开路由）；并发仍需原子防重复。
- 即使未初始化，也不得未经有效的一次性 bootstrap token 就创建管理员；无 token 应 fail closed。生产环境**不要因移除前端按钮而误以为接口已关闭**。
- 评估是否应配置生产 `TINYNEST_SETUP_DISABLED=true` 或同等受控开关：它只能附加保护，不可代替数据库已初始化判定和令牌校验。若添加开关，必须提供部署示例与回归测试，且默认安全，不破坏全新离线部署的受控初始化流程。
- 不允许依靠 `RemoteAddr=127.0.0.1` 判定安全（反向代理后的公网请求也可能显示 loopback），不得把 token 放在前端 bundle、URL、日志、仓库或 PWA 缓存中。
- 若生产系统存在“尚未初始化但无管理员”的异常状态，页面提供中性的部署运维提示，不自动公开创建管理员表单。
- 若仍需要恢复管理员，给出命令行/运维步骤与访问控制说明；不在公众页面提供恢复入口。

### 1.3 登录和权限

- 复核 `HttpOnly; Secure; SameSite` Cookie，可信代理来源白名单和 `/api` 禁止缓存；不泄露用户名是否存在。
- 账号失败限流、CSRF、防越权 `household_id`、登录重定向继续保持原有测试绿灯。

**P0 验收**：已初始化数据库下公开页面看不到 setup；HTTP 未认证直接调用 setup 无法创建管理员；数据库管理员计数和关键分录完全不变；首次部署受控 bootstrap 流程仍可在隔离环境使用。

## 2. P1：重做未登录公开首页（不改现有账务数据）

### 2.1 建议页面状态机

| 访客状态 | 入口呈现 | 操作结果 |
|---|---|---|
| 未登录 | 公共 Landing Page | 点「进入我的小家」才打开登录弹窗或前往 `/login` |
| 已登录 | 财务驾驶舱 `/dashboard` | 不再看到介绍页或登录表单 |
| 会话过期 | 返回 Landing 或登录视图，保留安全 return URL | 不显示私人数据、不得死循环 |
| 未初始化的受控安装 | 中性初始化提示/运维说明 | 不在公网自动开放 setup UI |

### 2.2 Landing 页面结构（PC 优先、移动兼容）

1. **顶部**：左侧原始团子图标 + `TinyNest` /「小家」；右侧简洁的「登录」入口。不要自动展开表单。
2. **Hero 首屏**：品牌标题「家的每一笔，都值得被温柔记录。」；副标题「从日常收支到账户与资产，让家庭的财务生活变得简单、清晰、有条理。」；一个主 CTA「进入我的小家」，一个轻量文字 CTA「了解功能」。
3. **品牌视觉**：原始糯米团子作为主视觉，不改绘图形；允许容器浮动、柔光、少量点缀，但不能添加屋顶、翅膀、新表情等到图片中。
4. **功能亮点**：日常收支、信用账单/分期、家庭资产、投资与分红、项目归集、自主托管（只有源码已实现并验证的功能可写成「已支持」；其余标「规划中」，可选择不展示）。
5. **工作方式/隐私说明**：可说「为自托管设计，数据保存在自有服务器」；不能未经验证保证「绝对安全」「银行级安全」「所有功能已完成」。
6. **页脚**：项目名称、GitHub 仓库、开发阶段状态、版权/版本（如有）。可附轻量开发阶段提示。

不要在公共首页使用任何真实家庭金额、成员姓名、账单截图、Cookie 中的私人信息；若采用功能演示图，必须明显标「演示数据」，不得调用私有 API。

### 2.3 登录弹窗/独立页

- 默认**关闭**；只在明确点击「登录/进入我的小家」或访问 `/login` 时显示。
- 不强制某种形式：优先模态框（PC）+ 移动端全屏抽屉/独立页，但须由现有路由结构决定，避免过度引入路由库。
- 正确处理 `Escape` 关闭、背景滚动锁定、焦点陷阱、`aria-modal`、关闭后焦点返回 CTA、错误提示、Enter 提交和 loading/防重复提交。
- 首次加载不能闪现登录框；退出登录后展示公共页面；登录成功按授权进入 Dashboard；受保护路由必须后端鉴权，不能只靠前端隐藏。
- 已登陆用户点击浏览器后退时不得暴露历史隐私页面的旧渲染内容。

**P1 验收**：首次进入只见介绍；点登录才见表单；成功/失败/退出/会话过期/直接访问受保护路由行为正确；PC、iPhone 均可操作。

## 3. P1：奶油团子动效规范（不要改绘图标）

整体气质：**微动、呼吸感、低刺激、轻巧、可读性优先**。只对 CSS transform/opacity 等低成本属性做动画，避免引发布局抖动。统一 tokens，减少重复散落的 magic numbers。

| 场景 | 方案 | 时长/幅度 |
|---|---|---|
| Hero 标题与按钮入场 | fade + translateY | 320–480ms；Y 8–14px；只执行一次 |
| 团子图标 | 非破坏性的 wrapper 浮动/呼吸 | 4–6s，位移 ≤ 5px；循环非常缓慢 |
| 登录弹窗 | opacity + scale | 200–260ms；缩放 0.97→1 |
| 路由主内容切换 | fade + 微位移 | 180–260ms；避免整屏闪烁 |
| 按钮 hover/press | 阴影 + transform | 120–180ms；translateY -1px，press scale 0.98 |
| 卡片 hover（有交互时） | 轻微抬升 | 160–220ms；Y ≤ 3px |
| 操作成功反馈 | 小型勾选/消息淡入 | 180–300ms；不撒花、不遮挡金额 |
| 表单错误 | 温和描边/提示淡入 | 不用反复强烈左右摇晃 |

颜色沿用已确定的 A「奶油团子」主题：奶油白、杏粉、暖棕；不使用高对比霓虹、强玻璃拟态或大量渐变。

**动效无障碍与性能门禁**：

- `@media (prefers-reduced-motion: reduce)` 下禁用无限浮动与非必要页面/弹窗动画，保留信息完整性。
- 禁止自动播放带声音的媒体、动效遮挡表单或造成误点。
- 禁止让真实财务数值通过乱跳的数字计数器逐次展示；涉及金额的状态应准确清晰。
- 重要信息无需等待动画完成才能读取；异步请求加载应有实际 loading 状态。
- 目标 LCP ≤ 2.5s、CLS ≤ 0.1（在可复现测试设备/网络条件下测量，不能无证据标 PASS）；动画不得引入明显掉帧。
- 保持浏览器兼容，不用重量级动画库实现简单淡入。优先 Vue `<Transition>` + CSS；确有复杂需求再论证依赖。

## 4. P1：PWA、缓存和隐私回归

- 已安装到 iPhone 主屏幕的旧版本可能仍缓存过去的登录/初始化页面。检查 service worker 升级机制、资源文件命名与版本号；确保可以获得新首页且不出现旧登录表单闪烁。
- Service Worker 仅缓存公开静态应用壳，**不缓存 `/api`、会话响应、包含私人财务数据的 HTML**。
- 无网络时，公共 Landing 可用，但所有财务 API 只显示正确的离线错误/待恢复状态；不伪造入账成功。
- 认证过期时从缓存恢复页面不得显示旧余额；登出需清除内存中的私人状态。

## 5. P1：验收与回归（必须可复现）

### 5.1 新增浏览器 E2E 场景（至少 14 条）

1. 未登录访问 `/` 默认 Landing，不出现登录表单和初始化页签。
2. 首屏不请求/渲染家庭财务 API 私有数据。
3. 点击「进入我的小家」出现登录表单。
4. `Escape` 关闭登录框（若使用弹窗）。
5. 关闭后焦点返回 CTA；键盘可完整操作。
6. 输入错误凭据显示友好错误，不泄露账号存在性。
7. 正确登录进入受保护 Dashboard。
8. 已登录刷新/访问 `/` 导航结果正确。
9. 未登录直接访问 `/dashboard` 被安全拦截。
10. 会话过期后不会闪现私人信息。
11. 登出后回到 Landing，清除私人页面状态。
12. 已初始化环境直接请求 `/api/v1/setup` 不能创建管理员。
13. 测试 `prefers-reduced-motion` 时图标无无限动画，登录功能正常。
14. 390/768/1440px 三视口无横向溢出，按钮和登录表单可用。
15. PWA SW 更新后旧初始化页签不再出现，`/api` 不缓存。
16. 用户在登录过程中刷新、后退、跳转不会进入重定向循环。

### 5.2 后端/回归

- 既有 `go test ./...`、`go vet ./...`、`go build ./...`、`go mod tidy -diff` 必须通过。
- Web `npm ci`、类型检查、生产构建、对应单元测试和浏览器 E2E 必须通过。
- 初始化/登录/会话/限流/CSRF/household 隔离至少各覆盖相应回归。
- 隔离 SQLite 空库受控 setup、已初始化库 setup 拒绝、数据备份→恢复的测试需通过；不可触碰生产 DB。
- CI 在 PR 对应 SHA 真实运行，并记录检查链接和结果；静态 YAML 解析 ≠ CI 通过。

### 5.3 视觉/交互验收

- PC 1440px、平板 768px、iPhone 390px 截图和键盘操作记录。
- 首屏视觉：原始图标不被改绘；无初始化入口；默认无登录框；CTA 明确。
- 动画：无布局跳动、重度眩晕、音效、页面切换死循环；按系统减少动态效果生效。
- 所有高风险 UI 路径（未登录、登录、退出、过期、后退、PWA 旧缓存）都能回归。

## 6. 交付和 Git/部署纪律

生成：

```text
docs/reviews/latest-code-audit.md           # 最新 SHA/源码/CI 证据，不能用旧报告冒充
 docs/plans/public-landing-motion-plan.md   # 更新后的实施决策和视觉规格
 docs/reviews/public-landing-security.md    # setup UI/API 与认证、隐私检查
 docs/reviews/public-landing-e2e.md         # E2E 命令、用例、截图、结果
 docs/reviews/public-landing-release.md     # 合并门禁/生产门禁分列
```

- 在独立开发分支完成源码和文档，测试通过后本地 commit；不擅自 push、merge、tag、上线、修改 DNS/证书/生产 DB。
- 允许报告 `DEV_READY`（可提交 PR 的开发候选）与 `PRODUCTION_READY`（正式上线）两套结论，不得混淆。
- 生产已经初始化的事实是**用户告知的环境状态**；未读取生产配置和实际 API 前，不得在报告标记「已现场验证」。
- 若在审计阶段发现未完成的财务账务 P0 缺陷，本轮先报告并阻断真实财务数据使用，不因视觉任务优先而忽略数据正确性。

**推荐实施顺序**：M0 最新代码核验 → M1 生产初始化安全收口 → M2 未登录首页 → M3 动效 → M4 E2E/PWA/CI → M5 PR 和独立预发布验收。
