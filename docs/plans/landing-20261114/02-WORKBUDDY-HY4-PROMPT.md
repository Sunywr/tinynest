## 第三步：P1 设计与开发未登录 Landing Page

未登录访问 `/` 应看到具有商业化气质的 TinyNest 官网式首页，而不是直接显示用户名/密码表单。

页面内容：
- 顶部：原始团子图标、TinyNest / 小家，右侧轻量登录入口。
- Hero：标题「家的每一笔，都值得被温柔记录。」；副标题「从日常收支到账户与资产，让家庭的财务生活变得简单、清晰、有条理。」。
- 主按钮「进入我的小家」→ 打开登录弹窗或 `/login`，只有点击时才出现账号/密码表单；次按钮「了解功能」→ 滚动到功能介绍。
- 亮点卡片：日常记账、账单与分期、项目归集、家庭资产、投资与分红、自托管隐私。必须先核对哪些已真正实现，未实现的不标「已支持」；可以标「规划中」。
- 页脚：项目 GitHub 地址、产品开发阶段说明，文字不堆积开发/运维文档。
- 不调用私人账务接口来绘制公开页，不显示真实资金/账户/家庭成员数据；如果展示示例数字，必须明确「演示数据」。

视觉：完全继承 A「奶油团子」：奶油白、杏粉、暖棕、圆润、留白、轻阴影。**直接引用用户的原始团子图标，不重新生成、不修改主体**；动画只能施加在图片的外层包装上。

交互：未登录、已登录、会话过期、退出登录、直接访问受保护路由等均有正确跳转。若使用模态框，支持 Escape、焦点管理、键盘操作与可访问性。不得产生重复登录、闪现私人金额或循环跳转。

## 第四步：P1 动效升级

建立统一 CSS 动效 tokens，优先 `<Transition>` + CSS，不引入大体积动效框架。

- Hero 标题/内容：320–480ms 淡入与 8–14px 轻上移。
- 团子容器：4–6 秒轻微呼吸/悬浮，位移不超过 5px，不改原图。
- 登录弹窗：200–260ms 淡入缩放。
- 路由与功能卡片：180–260ms 轻过渡。
- 按钮点击/hover：120–180ms，微小缩放和阴影。
- 成功/错误反馈：温和的状态过渡，不能遮挡重要金额或造成误操作。
- 必须实现 `prefers-reduced-motion`；不得自动播放声音、复杂粒子、闪烁动画；不能通过动画隐藏真实加载延迟。
- 财务驾驶舱金额要真实、稳定，不做花哨计数滚动而造成误读。

## 第五步：PWA、测试和性能验收

实现/更新浏览器自动化测试，至少覆盖以下 16 个场景：

1. 未登录首页不显示登录框和初始化页签。
2. 公开页不会触发私人账务接口获取。
3. 主 CTA 可打开登录表单。
4. 登录框可通过 Escape 关闭（若是模态框）。
5. 关闭后焦点回到按钮，键盘操作完整。
6. 错误登录提示合理，不泄露账户存在性。
7. 成功登录进入 Dashboard。
8. 已登录刷新或进入 `/` 行为正确。
9. 未登录深链访问受保护路由被阻止。
10. 会话过期时不会露出私人余额。
11. 登出后返回公共首页并清除敏感状态。
12. 已初始化状态直接调用 setup 不能创建新管理员。
13. 减少动态效果设置能停用持续动效。
14. 390、768、1440px 视口无横向溢出，表单和按钮可用。
15. 新版 PWA 更新后旧初始化页面不会残留；`/api` 仍不缓存。
16. 登录期间浏览器刷新/后退不会形成路由循环。

此外执行并记录：Go build/test/vet/tidy，Web npm ci/typecheck/build，真正的浏览器 E2E，SQLite 隔离库迁移/备份恢复，CI 真实绿灯，必要的安全回归。缺少运行环境时标 `UNVERIFIED`，绝不虚构通过。

对 LCP ≤ 2.5s、CLS ≤ 0.1 做可复现测量（记录设备/网络/样本），不能以主观感觉声称性能达标。确保 iPhone PWA Safe Area、触控、旧 SW 更新行为正确；没有 iPhone 真机就列出人工验证清单，不编造实机测试。
