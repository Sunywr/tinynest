# TinyNest V2 记账重置总计划

> 状态：计划稿（P4 交付）｜编写日期：2026-11-22｜适用分支：`v2-bookkeeping-reset`
> 关联文档：[记账模块规格](v2-bookkeeping-module-spec.md)、[三端优化计划](v2-platform-optimization.md)、[生产清理手册](v2-prod-purge-runbook.md)、[新库切换手册](v2-cutover-runbook.md)
> 验证口径：本文件中标注 UNVERIFIED 的事项，均未在本次文档编写环境执行或取得生产证据，验收时不得视为已通过。

## 1. 目标与成功标准

V2 的目标不是继续增加功能，而是把现状（140 条路由、55 张表、单文件 3,041 行的前端）收敛为可维护、可验证、手机端优先的记账产品：生产库只保留用户与权限数据；记账沿用复式内核，但对外简化为「流水」；界面结构与交互照鲨鱼记账重建，配色沿用奶油团子。

| 编号 | 目标 | 成功标准 | 验证方式 | 当前状态 |
| --- | --- | --- | --- | --- |
| G1 | 生产库仅保留用户与权限且可验证 | 业务数据行清空、11 张身份表数据完整；基线采集 → 清理 → 校验全绿；身份计数与迁移版本在清理前后一致 | `tinynest-admin verify`、隔离恢复比对、人工核对 dry-run 输出 | 未开始（UNVERIFIED） |
| G2 | 路由 140 → ≤55 且全绿 | 集中路由表可断言路由数 ≤55；Go 测试、前端构建、E2E 全部通过 | 路由断言测试与 CI 门禁 | 未开始（UNVERIFIED） |
| G3 | 记账模块手机端优先 | 390×844 与 1440×900 两个视口 E2E 全绿；主流程（打开记账 → 选分类 → 输入金额 → 保存）≤3 次点击 | Playwright 双视口用例与人工点按记录 | 未开始（UNVERIFIED） |
| G4 | 交付三端优化计划 | 前端、后端、数据端每个优化项都给出「为什么」与「如何验证」，并完成评审 | 文档评审与任务拆分记录 | 本批交付 |
| G5 | 每阶段有备份点可回滚 | 每阶段开始前有可校验备份；清理或切换失败时可恢复到最近备份点 | 备份 SHA-256 校验与恢复演练记录 | 未开始（UNVERIFIED） |

补充口径：

- G1 的「仅保留用户与权限」指业务数据行被清空，不要求删除 v1 库的表结构；清理工具只做数据删除（DML），因此可以在单事务内回滚，详见清理手册。
- G2 的「全绿」指仓库当前可执行的全部门禁通过；依赖生产环境、真机或不可用外部条件的项目按仓库规范标记 UNVERIFIED。
- G3 的「点击」只统计用户必须完成的显式操作，不计滚动、系统键盘弹起与页面加载。

## 2. 现状事实

### 2.1 度量基线

| 维度 | 现状（V1 基线） | V2 目标 |
| --- | --- | --- |
| 后端 Go 代码 | 121 文件、25,495 行；其中 `internal/api` 95 文件、21,503 行 | 后端非测试代码 ≤7,000 行（P2 实测 7,408 行，差 5.8%，未达标，如实记录） |
| 前端源码 | `src` 22 文件、5,794 行；`App.vue` 3,041 行单文件 | 前端单文件 ≤300 行（P3 实测最大 242 行，`styles.css` 除外） |
| HTTP 路由 | 138 + 2 = 140 条 | Register ≤55 条（P2 实测 55 条，`TestRouteBudget` 断言；另有 healthz/readyz 2 条不在 Register 内） |
| Go 测试 | 51 文件、189 个用例 | ≈120 个（P2 实测 99 个测试函数、21 文件） |
| Playwright E2E | 89 个（68 + 21） | ≈45 个（P3 实测 72 个） |
| SQLite 迁移 | 21 个版本 | 单一通用迁移器（基线 001–002；后续追加 003 分类颜色、004 信用卡账单配置，当前 4 个文件） |
| MySQL 迁移 | 14 个版本 | 单一通用迁移器（基线 001–002；后续追加 003 分类颜色、004 信用卡账单配置，当前 4 个文件） |
| 数据库表 | SQLite 与 MySQL 各 55 张表；无 `ON DELETE` 级联 | 55 → 25 张（运行时 26 张，含迁移账本 `schema_migrations`） |

统计口径说明：以上为当前工作树的静态清点结果（文件数、行数、路由与迁移版本数）；生产运行态数据、CI 实测耗时、E2E 执行结果仍为 UNVERIFIED。

### 2.2 现状问题

- 路由与代码体量大：140 条路由集中在 `internal/api` 的 95 个文件、21,503 行里，边界不清，新增能力会继续推高维护成本。
- 前端单文件化：`App.vue` 3,041 行，路由、状态、视图与样式耦合，无法按界面独立迁移和测试。
- 迁移双轨：SQLite 21 个版本、MySQL 14 个版本，版本号不齐；启动期存在副作用（每次 `db.Migrate` 执行 `UPDATE categories SET parent_id=NULL`），会改坏数据。
- 表多且无级联：双方各 55 张表，没有 `ON DELETE` 级联，退役与删除必须显式处理依赖顺序，否则会留下孤儿行。
- 测试结构与目标不匹配：Go 测试 189 个、Playwright 89 个，V2 目标约 120 与 45；需要随模块退役同步调整用例，而不是简单删除测试。
- 记账边界过宽：复式内核（`journal_entries` / `journal_lines` / 冲正）要保留，但 V1 的信用、分期、负债、投资、导入、邮件账单、股票、项目、拆分、退款全部退役。

### 2.3 已确认决策

| 编号 | 决策 | 落地位置 |
| --- | --- | --- |
| ① | 生产清理由用户执行，我们交付工具 + 手册 | 清理手册与运维 CLI |
| ② | 保留 用户 / 会话 / 角色 / 邀请机制 / 站点管理员 / 邮箱验证与 SMTP 配置 | 模块规格 §5 保留路由与 §6 身份表 |
| ③ | 保留复式记账内核（`journal_entries` / `journal_lines` / 冲正），重建 API、表与界面，对外简化为「流水」 | 模块规格 §5 与 §6 |
| ④ | 结构与交互照鲨鱼记账，配色沿用奶油团子 | 模块规格 §1、§3、§4 |
| ⑤ | V1 范围 = 记账键盘 / 按天明细 + 搜索 + 日历 / 环形图 + 分类排行 / 账户与转账 / 预算 / 家庭成员 / 导出 | 模块规格 §4 与本文 §6 |

说明：以上五项是本次重置的约束；评审出现冲突时以此表为准。需要调整时必须由用户确认并同步更新本表。

## 3. 阶段计划 P0–P5

阶段表示交付顺序与门禁，不代表时间承诺。每阶段开始前必须建立备份点（G5）；门禁未通过不得进入下一阶段。

### P0 冻结与基线

- 动作：同步并冻结 V2 分支；静态清点并固化 §2.1 度量；冻结 API 契约（模块规格 §5）与 DDL 关键表（模块规格 §6）；清点路由、死代码与退役模块；确认 §2.3 五项决策。
- 交付物：度量基线记录；路由清单；契约冻结评审记录；备份点清单（位置、SHA-256、恢复方式）。
- 门禁：度量可复现（同一统计脚本输出一致）；契约评审通过；备份恢复演练成功（演练结论 UNVERIFIED 前不得进入 P1）。

### P1 清理与身份迁移工具

- 动作：实现 `tinynest-admin`（`baseline-capture` / `purge` / `verify` / `identity-export` / `identity-import`，SQLite 与 MySQL 双驱动）；`purge` 只做数据删除（DML）且单事务执行；凭据只从文件读取；编写中断恢复与配置校验逻辑；补齐工具测试；交付清理手册。
- 交付物：运维 CLI 与测试；清理手册；脱敏后的 dry-run 输出样例；identity JSONL 格式说明。
- 门禁：`--dry-run` 只读且输出可人工核对；`--execute` 必须同时带 `--confirm=<DBNAME>` 与 `--yes-service-stopped`；单事务失败整体回滚；双驱动工具测试全绿；凭据不出现在命令行与日志。

### P2 V2 数据层与后端

- 动作：实现单一通用迁移器（嵌入文件名版本升序、记录 checksum、校验连续性、baseline 守卫）；落地 V2 DDL 并保留 11 张身份表；重建记账 API（categories / accounts / transactions / stats / budgets）；统计一律由分录派生；集中路由表并断言路由数；固定中间件链顺序；统一错误码、cursor 分页与幂等键；删除死代码。
- 交付物：V2 迁移与 `schema_meta`（baseline=v2）；API 契约实现与契约测试；路由清单；行数统计脚本。
- 门禁：路由 ≤55（实测 55，`TestRouteBudget` 通过）；后端非测试代码 ≤7,000 行（实测 7,408，未达标，已如实记录）；from-zero 迁移、checksum 篡改与 baseline 不符拒绝启动三类测试通过；统计口径与 `household_id` 作用域测试通过；Go 测试全绿（实测 99 个测试函数）。

### P3 前端三端与记账模块

- 动作：拆分 `App.vue`；引入 `vue-router` 4（唯一新增依赖）；设计 token 化；实现五个记账界面（账单 / 记账面板 / 图表 / 资产 / 我的）；实现自定义数字键盘；补齐移动安全区与 44px 触控；实现错误边界与离线提示；E2E 覆盖 390 与 1440 视口。
- 交付物：前端新结构（`App.vue` ≈200 行 + `router` + `views/` + `components/` + `composables/` + `services/`）；五个界面；E2E ≈45 个。
- 门禁：前端单文件 ≤300 行；390/1440 双视口 E2E 全绿；主流程 ≤3 次点击；唯一主题为奶油团子；品牌团子原图字节不变；行尾空白检查全绿。

### P4 文档与验收（本批）

- 动作：交付总计划、模块规格、三端优化计划、生产清理手册、新库切换手册；整理验收清单与证据模板；核对文档与代码、契约一致；澄清待决口径并登记 UNVERIFIED 项。
- 交付物：`docs/plans/` 下五份文档；验收清单；待用户处理事项清单。
- 门禁：五份文档齐全且无行尾空白；内容与五项决策一致；评审通过；所有未执行项均有 UNVERIFIED 标注。

### P5 生产清理与切换（用户执行）

- 动作：用户按清理手册执行生产清理，按切换手册建立 V2 新库并导入身份数据；我们提供工具、值守与问题定位；执行后设观察期，核对 `readyz` 与核心流程。
- 交付物：`docs/reviews/v2-purge-evidence.md`（执行人、时间、SHA-256、前后计数）；切换记录；备份保留记录。
- 门禁：`verify` 全绿；身份计数与摘要一致；`/api/v1/readyz` 返回 200；管理员登录与记账冒烟通过；备份与旧库保留 ≥30 天；证据齐备。

## 4. 数据清理范围

- 清理对象：v1 业务数据行，共 42 张表（分组、表名与边缘情况以清理手册 §4 为准）；另列「成员档案与邀请」3 张表（`household_members` / `household_user_members` / `household_invites`），合计 **45 张表** 在 `tinynest-admin purge` 白名单内，需在 dry-run 时确认去留：若 V2 继续提供家庭成员功能，这 3 张表按「清空后重建」处理，不随退役模块删除结构。
- 保留数据（11 张身份表）：`households`、`users`、`sessions`、`pending_registrations`、`site_administrators`、`email_identities`、`email_challenges`、`mail_configuration`、`mail_preferences`、`mail_daily_usage`、`mail_recipient_daily_usage`。
- 清空重建：`categories` 默认清理为空（严格口径），需要清理后继续使用 v1 界面时加 `-reseed-categories`；`accounts` 清空后必须先建账户才能记账，属预期；`transactions` 等流水表清空后界面显示空状态。
- 计数口径说明：清理只删除数据行、不执行 DDL，因此可以在单事务内回滚；v1 库仍保留空表结构，V2 的 25 张业务表目标由新库基线承担（见切换手册）。
- 密钥：32 字节 `mail-key` / `credit-mail-key` 必须单独备份；缺失会导致 `mail_configuration.password_cipher` 与 `mail_queue.payload` 不可解。

## 8. 明确不做

- 不做 v1 库原地升级：V2 不支持旧库直接升级；本地删除 `apps/api/data/tinynest.sqlite3`，生产新建库 + 导入身份数据 + 切 `TINYNEST_MYSQL_DATABASE`。
- 不重建退役模块（§5 全部）及其路由、视图、测试。
- 不新增主题或风格：唯一 A · 奶油团子；团子品牌原图字节不改。
- 不引入新框架或中间件栈；前端唯一新增依赖为 `vue-router` 4（理由见三端优化计划）。
- V1 不做：信用卡账单与分期、投资、账单导入、股票、邮件账单、多账本、多币种、离线补记账队列。
- V2.1 的 `internal/api` 分包重构不在 V2 范围。
- 不自动 `push` / `merge` / 部署 / 创建发布 tag（遵守仓库规范）。
- 不在文档、仓库或浏览器 JS 中出现真实域名、IP、主机名、口令或令牌。

## 9. 风险与回滚

| 风险 | 触发信号 | 影响 | 缓解 | 回滚 |
| --- | --- | --- | --- | --- |
| 清理后账务口径不一致 | 借款合计不等、`verify` 失败 | 记账结果不可信 | 清理前基线采集与隔离恢复比对；统计只从分录派生 | 单事务自动回滚；必要时恢复备份 |
| 清理中断 | CLI 非零退出 | 半清理状态 | 单事务执行；前后计数核对 | 整体回滚后重跑 |
| 服务未停导致并发写 | 检测到活动写入或健康检查通过 | 数据丢失或不一致 | `--yes-service-stopped` 人工确认；先切只读 | 恢复备份 |
| 加密密钥丢失 | 启动后 SMTP/IMAP 解密失败 | 邮件配置不可用 | 清理前单独备份密钥文件并登记保管人 | 无备份则不可恢复，只能重新配置（标注） |
| 路由收敛不足 | 路由断言失败 | G2 不达标 | P2 先删后并；删除死代码与退役模块路由 | 回退到 P2 备份点 |
| 前端拆分回归 | 双视口 E2E 失败 | 体验退化 | 逐界面迁移；先补测试再迁移 | 回退到 P3 备份点 |
| 身份导入列集合不一致 | 比对失败或导入报错 | 无法切换 | 导出前校验列集合；新库按基线重建 | 切回旧库与旧二进制 |
| 清理误删身份表 | 身份计数前后不一致 | 登录不可用 | 保留名单白名单 + 人工二次核对 | 从旧库备份恢复 |
| 备份不可恢复 | 恢复演练失败 | 无有效回滚点 | P0 起每阶段做恢复演练；隔离实例验证 | 不进入下一阶段 |
| 成员表去留误判 | 冒烟时 `/household/members` 失败 | 家庭成员功能不可用 | dry-run 前确认清单；成员表按清空重建处理 | 恢复备份后重建 |

回滚总原则：

- 每阶段开始前建立备份点，并记录位置、SHA-256 与恢复方式；没有有效备份点不得执行破坏性操作。
- 清理在单事务内完成，失败整体回滚；已提交后的回滚等于从备份恢复。
- 生产清理与切换只能由用户执行；执行人、时间、SHA-256 与前后计数必须写入证据文件。
- 旧库与备份保留 ≥30 天；30 天内不得删除任何回滚材料。
