## 0. 已知项目边界

- 产品：TinyNest / 小家，自托管家庭记账系统。
- 前端 Vue 3 + TypeScript + Vite；后端 Go；SQLite 单实例账务数据库。
- 前、后端部署在不同服务器；PC Web + iPhone PWA。
- 「奶油团子」配色和用户提供的原始糯米团子图标不得改绘。
- 上一轮要求：未登录首页展示项目介绍、默认不显示登录表单、点击按钮才登录；公开初始化页签移除；首页/切换加入温柔轻量动效，支持 `prefers-reduced-motion`。
- 用户确认**生产环境已初始化**，但没有明确授权使用生产数据测试、生产迁移或重新部署；默认全部禁止。
- 历史审查显示曾有 `/setup`、家庭隔离、时区、Secure Cookie、登录限流等问题，随后用户提供报告称已修复；新代码仍需回归验证，不可沿用旧结论作为本次 PASS。
- 历史开发计划曾列 S3～S7、投资费率、自动到期等缺口；最新是否完成**必须由代码和运行结果决定**。

## 1. M0：必须先独立建立最新代码基线

### 1.1 Git 和版本

在独立、无敏感数据的工作区执行：

```bash
git status --porcelain=v1
git remote -v
git fetch origin --prune
git branch -avv
git rev-parse HEAD
git rev-parse origin/main
git log --all --graph --oneline --decorate -25
git diff --stat origin/main...HEAD
```

读取最近 PR / CI 状态；如有 GitHub CLI，读取实际检查结果；如无，使用有权限的浏览器或 GitHub API。只对可验证的最新 SHA 下结论。若远程不可达，记录 `REMOTE_UNVERIFIED`，不要拿历史 SHA 假装最新。

先检查已有未提交文件；**禁止** `git reset --hard`、`git clean -fd`、force push、修改 main、自动合并。

### 1.2 功能完成度矩阵

请逐行输出：`要求 / Git SHA / 源码文件:行号 / 前端入口 / API 路由 / 数据表及迁移 / 测试用例 / 实测结果 / 状态 / 缺陷编号`。

状态只能是 `PASS`（真实代码+实测通过）、`PARTIAL`、`UI_ONLY`、`MISSING`、`UNVERIFIED`、`BLOCKED`。

| 检查对象 | 要求 |
|---|---|
| 公开首页 | 未登录默认展示品牌介绍，不请求私人财务数据；不直接显示登录表单或初始化页签 |
| 登录交互 | 由 CTA 打开，失败提示、Escape、焦点管理、成功跳转、退出和会话过期完整 |
| 初始化安全 | 已初始化数据库下任何访问均无法再次创建 admin；未初始化时无有效 bootstrap 凭据不得创建 |
| 动效 | 页面/弹窗过渡柔和；减少动态效果设置生效；原图标 hash 不变 |
| PWA | 192/512/180 图标、manifest、Service Worker 更新；不缓存 `/api` 或私有财务状态 |
| 收支与账户 | 账户余额可重算、账户转账不算收支、分类/项目拆分、退款与冲正 |
| 信用工具与账单 | 账期/还款日、额度、状态、提前/部分还款、对账差额 |
| 房贷/保险与分期 | CRUD、期次、部分付款、利息/手续费、本金转换、信用工具支付、冲正 |
| 投资 | 交易费率配置与快照、买卖成本、分红税未知值、手工估值、收益 |
| 定时调度 | 重启补扫、按期生成待办、20 次重复执行不重复、不自动确认付款 |
| 首页/报表 | 收支、现金流、到期应付、净资产、投资收益分别有可追溯明细 |
| 运维安全 | 家庭数据隔离、CSRF、限流、Secure Cookie、可信反代、SQLite 迁移/备份恢复、CI |

## 2. 版本优先级与智能分流

### Gate A：安全与账务先行

若存在 `/setup` 未授权创建管理员、会话泄露、跨家庭读写、账务不平衡、分期/信用重复入账、生产数据迁移风险，立即视作 P0：**本轮先修复，阻止发布**。

### Gate B：先核验上一轮体验改造

若未登录 Landing、登录弹窗、关闭初始化入口、动效或 PWA 更新任一没有真实 E2E 证据，优先补测试并修复实际缺陷。若已经达到 PASS，跳过开发，不改 UI。

### Gate C：补闭环，不重造

- 信用账单、分期、房贷/保险、调度、投资费率、独立报表：只对 `MISSING/PARTIAL` 项开发。
- 已通过的后端/API/页面/迁移不重写；宁可补边界测试和文档。
- 十项账务规则确认状态只按用户明确批准记录，未确认保持 `PENDING_USER_CONFIRMATION`。

### Gate D：走向生产前的「预发布」

所有关键功能和 E2E 都达标后，制作**隔离预发布清单**，在独立测试库和测试域名演练前后端双服务器 HTTPS、PWA 安装、升级、备份恢复。未经用户明确授权，不执行真实服务器部署。

## 3. 本轮推荐实施里程碑

### M1 — 最新代码独立核验

交付 `docs/reviews/current-sha-and-coverage.md`、实测命令与日志、API/页面完成度矩阵、CI 检查状态。

### M2 — 公开入口与认证安全收尾（按证据修复）

- 游客默认 Landing；无公开初始化页签、按钮或深链；登录表单仅在明确操作后显示。
- 后端已初始化状态坚决拒绝 setup，不通过 `127.0.0.1` 反代假定安全；保留受控新装初始化流程。
- 登录失败限流、Secure/HttpOnly/SameSite Cookie、CSRF、可信代理白名单、会话过期与退出清理。
- 未登录页面不泄露家庭姓名、账户余额、私人 API 或缓存；点击登录正确跳转到受保护页面。
- 原始图标一致，奶油团子设计不变；CSS transform/opacity 微动、弹窗过渡、`prefers-reduced-motion`。
- 页面在 390/768/1440px 均操作正常，键盘焦点可见，弹窗可 Escape 关闭并恢复焦点。

### M3 — 财务可靠性与业务闭环（按证据修复）

- 人民币整数分/定点数；复式记账平衡；已入账冲正；接口事务及幂等。
- 信用消费 → 部分还款 → 退款 → 结清；贷款本息/保险通过信用卡支付；分期部分付款、退款及后续计划调整。
- 自动到期任务绝不自动确认实际支付；跨月、闰年、跨年计算正确。
- 投资移动加权平均成本、历史费率快照、红利税可空、分红收益和估值日期。
- 账务首页不能将信用还款当费用、将证券买入当消费、将贷款本金当费用。

### M4 — 自动化 E2E、CI 与发布可靠性

- 使用临时 SQLite 库、模拟家庭和不含真实数据的浏览器测试。
- 至少 18 条端到端场景，覆盖游客→登录→记账→信用账单→房贷分期→投资→登出等主路径。
- PC 1440、平板 768、手机 390；`prefers-reduced-motion`；旧 PWA 缓存升级。
- 后端 Go build/test/vet/tidy，前端 typecheck/build/test，GitHub Actions **对当前 commit 真实绿灯**。
- SQLite 空库迁移、旧库无破坏升级、备份到隔离库恢复，核对分录、余额、合同与投资持仓一致。
- 没有对应设备时 iPhone Safari 实机项目标注 `MANUAL_UNVERIFIED`，禁止伪称通过。

### M5 — 形成发布候选，而不是直接上线

- 生成 `docs/reviews/rc-readiness.md`，分开标记 `DEV_READY`、`STAGING_READY` 和 `PRODUCTION_READY`。
- `PRODUCTION_READY` 除技术门禁，还需要十项账务规则获用户确认、真实 HTTPS 可信代理与 PWA 实机验证、生产备份恢复预案和明确上线授权。
- 未经用户授权不得自动 push/merge/tag/生产部署；可在独立工作分支本地提交。

## 4. 量化验收指标

| 指标 | 通过标准 |
|---|---|
| 最新 SHA | 远程 `main` 与工作分支 SHA、时间、关联 CI 有可核查来源 |
| 公开初始化入口 | 0 个（包括直达路由与旧缓存可见入口） |
| 已初始化后新增 admin | 0 个；受保护 setup API 仅按规则拒绝 |
| 未登录首页私人信息泄露 | 0 个；不调用需认证的财务查询来生成展示数据 |
| 主要浏览器场景 | ≥18 条，全部通过（不可执行则 `UNVERIFIED`） |
| 关键视口 | 390 / 768 / 1440px，无关键功能阻断 |
| 账务借贷 | 100% 平衡；金额/余额错误 0 分 |
| 冲正/退款/分期幂等 | 20 次重复请求，重复入账 0 笔 |
| 多家庭越权 | 0 项；同一临时库双家庭验证 |
| 定时到期事项 | 20 次执行，仅生成一份待办且未自动付款 |
| 动效无障碍 | `prefers-reduced-motion` 下非必要动画停用；键盘/焦点可用 |
| Go / Web / CI | 适用构建及测试 exit 0，CI 当前 SHA 真实绿灯 |
| 迁移与备份 | 空库初始化、升级、恢复、`quick_check` / `foreign_key_check` 通过 |
| 发布阻断缺陷 | P0=0、P1=0；否则不得出 `READY` |

## 5. 使用真实财务数据前的硬性前提

1. 正式明确并确认 `docs/reviews/v0.1-accounting-decisions.md` 的十项账务口径；不得由 Agent 假装确认。
2. 生产环境初始化已完成：绝不清库、重新 setup、重置管理员或擅自运行迁移。
3. 生产前建立带校验的离线/异地备份及恢复方案，在**隔离副本**演练，不在生产数据库上做破坏性测试。
4. 前端服务器和后端服务器的 TLS、可信代理、访问控制、服务配置和密钥管理经实际验收。
5. iPhone PWA 实机安装/更新/登出测试由用户执行或提供证据，不能使用模拟器替代并声称实机通过。
