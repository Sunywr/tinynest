## 2. 版本策略：先识别，再选择实施路线

**路线 A：V0.1.1 仍有 P0/P1 缺口（优先采用）**
只补真实缺口，直到完整实现“消费 → 信用出账 → 退款/分期 → 贷款/保险付款 → 还款 → 自动待办 → 首页核对”，并通过真实 E2E、数据一致性和 CI。不要开 V0.1.2 的新功能。

**路线 B：V0.1.1 已通过完整门禁**
进入 **V0.1.2：投资管理与财务报表完善**，按依赖顺序推进：

1. 投资费用规则：佣金费率/最低费用、印花税、过户费、其他费用；按交易市场/方向/日期及账户配置生效，单笔可覆盖并保存历史快照。
2. 投资交易全闭环：股票/ETF/理财买卖、建仓/加仓/减仓/清仓、份额、资金流水；严格按既有成本法计算已实现与未实现收益。
3. 分红：税前金额、可选税额（未知不等于零）、税后金额、到账账户，确保现金分红和收益统计不重复。
4. 投资报表：当前数量、成本、市值（手动估值）、已实现/未实现收益、净分红、历史累计买入成本，以及**口径明确**的综合收益；显示价格/净值日期，禁止“实时行情”假象。
5. 家庭总览：资产构成、负债结构、收支趋势、项目累计支出、信用工具月账单与未来到期；报表每项可点击明细核对。
6. PC Web + iPhone PWA：小屏表单、数量/金额输入、操作确认、空状态、错误信息和奶油团子设计一致性。

**路线 C：投资/报表也已达到门禁**
本轮不继续堆功能，优先 **V0.1.3 预发布可靠性**：隔离预发布环境、双服务器 HTTPS、权限、PWA 实机、自动备份/恢复、真正 CI 和 E2E；仍不得以预发布代替生产批准。

## 3. Milestone 及量化验收

### M0 · 最新仓库事实盘点（必须先执行）

- `git fetch --all --prune`，读取 `main`、remote heads、最近提交、未合并 PR、CI；确认用户最新提交在哪个分支。
- 执行本地等价构建/测试；不得将 `README` 或旧报告视为新代码测试结果。
- 从源码、API、迁移、前端路由和自动化测试形成 `Feature × Evidence` 矩阵，标记 `PASS/PARTIAL/UI_ONLY/MISSING/UNVERIFIED`。
- 形成**与上一轮 V0.1.1 M0～M6 的差异表**，剔除已完成任务。
- 记录历史安全修复是否仍存在，尤其 setup 保护、SQL 家庭隔离、COOKIE Secure、登录限流。

**门禁**：能够给出最新 SHA/分支、已实现 API、缺失接口、测试证据和有优先级的开发 backlog。没有核实之前不能说 V0.1.1 已完成。

### M1 · 填补 V0.1.1 真实缺口（条件执行）

- 只针对尚未通过的信用账单生命周期、部分还款、退款、固定负债/保险、分期期次、每日待办、首页统计、浏览器 E2E 修复。
- 核心会计不变量：**借贷平衡、整数金额、事务原子、幂等、分期本金不重复、信用卡还款不计费用、账户转账不计收支、退款关联原单、家庭数据隔离**。
- 核查分期部分付款的本金/费用分配：待用户确认时，显式输入两项拆分，禁止默认将未知规则当成已确认。

**门禁**：所有适用场景全通过，P0=0、P1=0，至少 12 条完整浏览器 E2E 实测通过，核心 API 不可伪保存。

### M2 · 投资费率与收益核算（仅 V0.1.1 已通过时执行）

- 费率规则 CRUD、账户关联、费用预览、单笔覆盖、历史费率快照与日期生效。
- 买入费用进持仓成本，卖出费用减净收入；不得把股票买入当消费。
- 交易和估值采用整数分/固定精度，不能用 float 做货币核算。
- 移动加权平均成本法与当前仓库既有实现一致；未取得用户新的明确授权前，不能偷偷换 FIFO 或税务规则。
- 投资金额、净分红、资金账户、成本和投资报表互相一致。
- 理财份额、净值、赎回、现金流和账户净资产完整核对。

**数值回归**：100 股×10 元+5 元手续费，追加 100 股×12 元+5 元手续费，持仓 200 股成本 2210 元；卖出 50 股×13 元、卖出费用 5 元，净入账 645 元、结转成本 552.50 元、已实现收益 92.50 元；余 150 股成本 1657.50 元；若最新估值 14 元，未实现收益 442.50 元；税前分红 100 元、税 10 元，净分红 90 元。若税额未知，显示“未填写/未知”，不以 0 替代。

### M3 · 报表与家庭资产核对（仅前置模块通过时执行）

- 首页按自然月及自定义任意起止日期展示：收入、费用、结余、实际现金净流量、本期到期/已还/逾期、可用现金、信用负债、贷款本金、投资市值和收益、家庭净资产。
- 支出按业务发生日，现金流按现金实际发生日，到期义务按约定日期；不得把三者混同。
- 资产负债表满足 `资产 - 负债 = 净资产`，并有底层明细可追踪。
- 项目、二级分类、拆分流水、跨月退款的汇总与交易相符。
- 数据不足时显示 `暂无数据` / `估值日期` / `待确认`，不能使用 Mock 充数。

### M4 · 真实浏览器、CI 和数据可靠性

- Go build/test/vet/tidy，全 exit 0；Web npm ci/typecheck/build 全 exit 0。
- E2E 至少 **12 条**（如果当前已有更多，保留现有更高基线），全 PASS；PC 1440 / 平板 768 / 手机 390 无操作阻断。
- 使用独立临时 SQLite 测试库执行初始化、升级、幂等迁移、完整备份恢复、`quick_check`、`foreign_key_check`。
- 同一记账提交/还款/分期任务重复或并发调用 20 次，最终账务仅入账一次。
- 跨家庭数据查询、修改、退款、付款、投资交易 0 越权。
- GitHub Actions 必须真实绿灯，若无授权 push，则将 CI 保持 `UNVERIFIED` 并要求用户操作。
- 没有 iPhone 实体设备时不得声称 PWA 实机通过，需列出手动检查项。

## 4. Git 与生产边界

- 从最新目标分支创建新独立 Worktree 或 feature 分支；保护所有未提交内容，不用 `reset --hard`、`clean -fd`。
- 不直接改 `main`，不擅自 force push、自动合并、打发布标签、部署两台正式服务器。
- 本轮可在新分支**本地提交**，未经额外明确授权不 push；已有用户推送的新分支保持不变。
- 无论新代码完成度多高，未经确认 10 项账务规则、HTTPS/可信反代、双服务器、iPhone PWA、备份恢复及安全验收，都不能宣布可录入真实家庭财务数据。
