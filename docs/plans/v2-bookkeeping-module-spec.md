## 1. 设计基线

结构与交互模仿鲨鱼记账，配色、圆角与字体沿用设计规范的唯一主题 A · 奶油团子；品牌团子原图字节不改，唯一批准 SHA-256 以 `assets/brand/README.md` 为准，本文件不重复记录。

| 维度 | 基线 | 约束 |
| --- | --- | --- |
| 结构 | 鲨鱼记账 | 底部 5 槽导航；中间凸起记账键；键盘式记账面板；分类图标网格；按天分组明细；日历；环形图 + 分类排行；资产管家 |
| 交互 | 鲨鱼记账 | 点击流水行 = 更正；长按流水行 = 删除（冲正）；自定义数字键盘常驻；保存成功 toast + 乐观插入；失败内联错误条 + 重试；离线绝不伪造成功 |
| 配色 | 设计规范 A · 奶油团子 | 背景 `#FCF7F0`；卡片 `#FFFEFA`；主色 `#DA8E7D`；正文 `#624D41` |

| 字体 | 系统字体 | PingFang SC、Microsoft YaHei、sans-serif |
| 品牌 | 团子原图 | 字节不改；不得改绘或重新生成图标 |
| 主题 | 唯一风格 | 不新增第二主题，不做主题切换 |

## 2. 设计 token

新增 token 如下；其余颜色继续使用设计规范已有 token。新增口径：`--tab-h:56px`、`--keypad-key:52px`、`--sheet-radius:24px 24px 0 0`、`--amount-size:34px`、8 色分类柔和底色。

| token | 值 | 用途 |
| --- | --- | --- |
| `--tab-h` | `56px` | 底部 5 槽导航高度（<768px 生效） |
| `--keypad-key` | `52px` | 数字键盘按键尺寸 |
| `--sheet-radius` | `24px 24px 0 0` | 底部面板顶部圆角 |
| `--amount-size` | `34px` | 账单「本月支出」主金额字号 |
| `--touch-min` | `44px` | 所有可点击元素最小热区 |
| `--cat-1` … `--cat-8` | 8 色分类柔和底色（具体色值 P3 设计评审冻结，UNVERIFIED） | 分类图标底色 |

沿用 token（与设计规范一致）：

| token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#FCF7F0` | 页面背景 |
| `--card` | `#FFFEFA` | 卡片背景 |
| `--primary` | `#DA8E7D` | 主按钮、数据条、选中态 |
| `--text` | `#624D41` | 正文 |
| `--muted` | `#A28F82` | 次要文字 |
| `--border` | `#EFE5DC` | 边框与分割线 |
| `--soft` | `#F9E8DF` | 柔和填充 |
| `--radius-card` | `21px` | 卡片圆角 |

交互与动效约束：

- 触控目标 ≥44×44：导航槽、分类网格、键盘键、行内按钮、弹层关闭键的点击热区都不得小于 44×44；视觉尺寸可以更小，但热区必须补足。
- `prefers-reduced-motion: reduce` 时禁用所有非必要动效（面板弹起、环形图绘制、toast 位移），只保留瞬时状态切换；不得以动画作为唯一反馈手段。
- 8 色分类底色与 emoji 组合使用；底色只用于图标容器，不改变文字颜色，避免与正文对比度冲突。

## 3. 断点与布局

| 视口 | 布局 | 记账入口 | 验收口径 |
| --- | --- | --- | --- |
| <768px | 底部 5 槽导航（高 56px）；记账面板贴底、顶部 24px 圆角；列表内容底部预留导航与安全区高度 | 中间凸起记账键 → 底部面板 | 390×844 E2E 必测 |
| 768–1023px | 沿用底部导航；内容最大宽度受限（具体值 P3 冻结，UNVERIFIED） | 同上 | 回归即可 |
| ≥1024px | 左侧 226px 轨道导航；内容居中；记账为居中弹层（modal） | 轨道上的记账按钮或内容区按钮 | 1440×900 E2E 必测 |

移动注意事项：

- 使用安全区变量（如 `env(safe-area-inset-bottom)`）避免底部面板与导航被系统手势区遮挡。
- 面板打开时锁定背景滚动；备注输入触发系统键盘时，面板整体上移或滚动，保证输入行与完成键可见。
- 390 与 1440 是两个必须全绿的验收视口；中间断点只做回归，不作为主验收口径。

可访问性要求：

- 日期组使用标题层级（如 `<h3>`），流水行使用列表语义；屏幕阅读器可按日期跳转。
- 金额输出可读文本（「支出 128 元」），不能只靠颜色区分收入 / 支出。
- 图标按钮必须有 `aria-label`（搜索、选择日期、上个月、下个月）。
- 长按删除必须提供等价的键盘 / 读屏入口（行内操作菜单），长按不是唯一方式。
- 错误条与空状态使用 `role="status"` / `aria-live="polite"`；焦点在重试按钮上保持可见。
- 触控热区 ≥44×44；正文与副文对比度符合设计规范。

元素清单：

| 元素 | 内容与规则 | 交互 | 备注 |
| --- | --- | --- | --- |
| 分段控件 | 支出 / 收入 / 转账 | 切换类型；切换后分类网格与 meta 行按类型变化 | 转账时隐藏分类，显示转出 / 转入账户 |
| 金额显示 | 右对齐大号金额；初始 0.00；整数分处理 | 数字键盘输入；`⌫` 删除末位 | 不使用系统数字键盘 |
| 分类网格 | 4 列图标网格；支出 / 收入各自分类；`⋯更多` 展开其余分类 | 点按选中，选中态高亮 | 分类名过长时截断并保留完整名称 |
| 备注行 | 📝 备注：可空 | 点按进入输入；允许系统键盘 | 键盘弹起时面板上移，不遮挡输入行 |
| 日期行 | 📅 今天（默认业务日期） | 点按打开日期选择 | 可选历史日期与跨月日期 |
| 账户行 | 💳 现金 ▾；默认为上次使用账户 | 点按选择账户 | 转账时为转出 / 转入两个账户 |
| 成员行 | 👤 我 ▾ | 点按选择成员 | 家庭成员为单选 |
| 数字键盘 | `1-9`、`.`、`0`、`⌫`、完成 | 常驻面板底部，不触发系统键盘 | 按键热区 ≥44×44 |
| 完成键 | 保存流水 | 保存中禁用；成功 toast + 乐观插入；失败内联错误条 + 重试 | 幂等键防止重复提交 |

交互规则：

- 记住上次分类与账户：`localStorage` 只保存分类 ID 与账户 ID，不保存名称、金额或备注；读取失败时回退到默认分类 / 默认账户。
- 保存中：禁用完成键、关闭键与分段切换，防止重复提交；完成键显示处理中状态。
- 成功：toast 提示「已保存」，账单列表乐观插入新流水，后台刷新后以服务端数据为准。
- 失败：面板内显示内联错误条 + 重试；输入内容与选择全部保留。
- 离线：明确显示「网络不可用，未保存」，完成键不可用；绝不本地伪造成功，也不做离线补记账队列（V1 不做）。
- 桌面（≥1024px）：面板为居中弹层；Enter 保存、Esc 关闭；关闭前若有未保存输入需确认。
- 转账：转出账户与转入账户不能相同；无账户时引导先到「资产」创建账户。

状态矩阵：

| 状态 | 界面表现 | 恢复方式 |
| --- | --- | --- |
| 默认 | 面板打开，金额 0.00，预选上次分类 / 账户 | — |
| 加载 | 分类与账户区域骨架，完成键禁用 | 自动完成 |
| 空 | 无分类：提示先到「我的 → 分类管理」创建；无账户：提示先建账户 | 跳转对应管理页 |
| 错误 | 面板内联错误条 + 重试；保留输入 | 点按重试或修改后重存 |
| 离线 | 顶部「网络不可用，未保存」；完成键禁用；已输入内容保留 | 网络恢复后重新保存 |
| 保存中 | 完成键与关闭键禁用；防止重复提交 | 成功 toast 或失败错误条 |
| 只读角色 | 面板不可打开；入口禁用并说明只读 | — |

可访问性要求：

- 分段控件用 `role="tablist"` / `aria-pressed` 表达当前类型；金额输入有明确 label 与实时数值播报。
- 分类按钮 `aria-pressed`；数字键盘按键有 `aria-label`；`⌫` 按钮播报「删除」。
- 弹层实现焦点陷阱，打开时焦点落在金额区域，关闭后焦点回到触发按钮；Esc 关闭、Enter 保存。
- 错误条 `role="alert"`；保存中通过 `aria-busy` 标记。
- 关闭按钮、完成键与所有键盘键热区 ≥44×44；`prefers-reduced-motion` 下不播放面板动效。

V2 账户口径（必须如实标注在界面上）：

- V1 账户类型仅 `cash | credit` 两种。
- 信用卡只是负债账户：支出增加欠款，还款按转账处理（**现金 → 信用卡**），不是收入或支出。
- 支持在账户上配置账单日与还款日，用于估算发薪日前需准备的现金；**不提供**银行级出账账单、分期、利息、最低还款或自动扣款，也不恢复 V1 的 `credit_statements` 账单表。
- 账户余额由 `journal_lines` 派生，禁止直接改余额；错账用冲正。

### 5.5 关键行为约定

- `PATCH /transactions/{id}`：更正 = 冲正原分录 + 按新值重新入账，两步在同一事务内完成；失败整体回滚。
- `DELETE /transactions/{id}`：冲正，不物理删除；已冲正流水不可再次冲正。
- `POST /accounts/transfers`：写入复式分录；转账不计入收支统计。
- `GET /stats/*`：一律由 `journal_lines` 派生；转账、冲正按规则计入或剔除，统计结果必须能与分录核对。
- `GET /budgets/{month}` / `PUT /budgets/{month}`：`month` 为 `CHAR(7)` 的 `YYYY-MM`；未设置预算返回空值而非 0。
- `GET /accounts/{id}/journal`：返回该账户相关分录行（含冲正标记），只读。
- 离线策略：V1 不做离线补记账队列；网络失败必须提示「网络不可用，未保存」，恢复后由用户重试。

### 5.6 数据流规则

- 所有统计一律由 `journal_lines` 派生；不得用 `transactions.amount_minor` 累加出报表。
- `household_id` 必须在 SQL 层限定；禁止先全库聚合再在应用层过滤。
- 流水行只保存 `category_id`，不保存分类名称 / emoji 快照；分类改名即时反映到历史流水，删除统一按停用处理。
- 账户余额由分录重建，禁止直接改余额；已入账分录不可变，纠错只用冲正。
- 每次写入流水必须同事务写入 `journal_entries` + `journal_lines`；不允许只写流水不写分录。
- 路由总数按「方法 + 路径」计；P2 冻结时以集中路由表断言目标 ≤55，超出则按「先删退役路由、再合并同类资源」收敛，候选合并项在 P2 评审记录中冻结（UNVERIFIED）。
- 信用卡还款计划通过现有 `GET /accounts?include=credit_debt` 投影提供，不新增路由；`include` 只接受空值或 `credit_debt`。

### 6.2 新增表 DDL

以下为逻辑 DDL；SQLite 使用 `TEXT` / `INTEGER`，MySQL 使用对应的 `VARCHAR` / `BIGINT` / `TINYINT`，类型映射由迁移器适配。金额一律整数分。

```sql
CREATE TABLE categories (
  id            TEXT PRIMARY KEY,
  household_id  TEXT NOT NULL REFERENCES households(id),
  kind          TEXT NOT NULL CHECK (kind IN ('income','expense')),
  name          TEXT NOT NULL,
  emoji         TEXT NOT NULL DEFAULT '',
  sort          INTEGER NOT NULL DEFAULT 0,
  active        INTEGER NOT NULL DEFAULT 1,
  created_at    TEXT NOT NULL,
  UNIQUE (household_id, kind, name)
);
CREATE INDEX idx_categories_household ON categories(household_id, kind, active, sort);

CREATE TABLE accounts (
  id              TEXT PRIMARY KEY,
  household_id    TEXT NOT NULL REFERENCES households(id),
  kind            TEXT NOT NULL CHECK (kind IN ('cash','credit')),
  subtype         TEXT,
  name            TEXT NOT NULL,
  owner_member_id TEXT,
  ledger_code     TEXT NOT NULL,
  status          TEXT NOT NULL DEFAULT 'active',
  note            TEXT,
  created_at      TEXT NOT NULL,
  UNIQUE (household_id, ledger_code)
);

CREATE TABLE transactions (
  id              TEXT PRIMARY KEY,
  household_id    TEXT NOT NULL REFERENCES households(id),
  type            TEXT NOT NULL CHECK (type IN ('expense','income','transfer')),
  amount_minor    INTEGER NOT NULL CHECK (amount_minor > 0),
  occurred_on     TEXT NOT NULL,
  category_id     TEXT REFERENCES categories(id),
  account_id      TEXT REFERENCES accounts(id),
  to_account_id   TEXT REFERENCES accounts(id),
  member_id       TEXT,
  note            TEXT,
  status          TEXT NOT NULL DEFAULT 'posted' CHECK (status IN ('posted','reversed')),
  entry_id        TEXT NOT NULL REFERENCES journal_entries(id),
  idempotency_key TEXT,
  created_by      TEXT,
  created_at      TEXT NOT NULL,
  UNIQUE (household_id, idempotency_key)
);
CREATE INDEX idx_tx_household_date ON transactions(household_id, occurred_on, type);
CREATE INDEX idx_tx_category ON transactions(household_id, category_id, occurred_on);
CREATE INDEX idx_tx_account ON transactions(household_id, account_id, occurred_on);

CREATE TABLE budgets (
  household_id TEXT NOT NULL REFERENCES households(id),
  month        CHAR(7) NOT NULL,
  amount_minor INTEGER NOT NULL CHECK (amount_minor >= 0),
  PRIMARY KEY (household_id, month)
);

CREATE TABLE schema_meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```
> 实现纠偏（2026-11-26 实测）：`001_core.sql` 实际列名是 **`meta_key`**（`meta_key TEXT PRIMARY KEY, value TEXT NOT NULL`），因为 `key` 是 MySQL 保留字。切换/清理手册的核对 SQL 已按 `meta_key` 写；照本段 DDL 手写的查询在 MySQL 上报 `ERROR 1054 (42S22): Unknown column 'key' in 'where clause'`。

约束与约定：

- `categories` 为单层分类（`level=1`），移除 `parent_id` 与二级分类。
- `accounts.kind` 仅 `cash` | `credit`；信用卡是负债账户，`ledger_code` 关联保留的 `ledger_accounts`；`statement_day` / `due_day` 可空、仅信用卡使用，不建账单表。
- 2026-11-22 扩展：`investment_accounts` / `investment_holdings` 只保存 pfm 导入的证券/理财估值快照，不写分录、不参与转账；资产页的投资市值与含投资净资产必须标注为估值视图。
- `transactions` 的 `category_id` 仅支出 / 收入使用；转账时为空，使用 `account_id` 与 `to_account_id`。
- `transactions.idempotency_key` 与 `household_id` 组合唯一，重复提交返回同一结果。
- 表之间不新增 `ON DELETE` 级联，删除顺序显式处理（与现状一致，避免隐式误删）。
- `schema_meta` 写入 `baseline=v2`，启动时校验；版本或 baseline 与二进制不符则拒绝启动。

### 6.3 表数目标

V2 目标表数为 27（55 → 27，运行时 28）。逐表清单：`001_core.sql` 21 张（身份 14 张、审计 1 张、邮件/元数据 2 张、复式内核 4 张，其中 `schema_meta` 为基线元数据）＋ `002_bookkeeping.sql` 4 张（`categories` / `accounts` / `transactions` / `budgets`）＋ `005_investments.sql` 2 张（`investment_accounts` / `investment_holdings`），另加代码创建的 `schema_migrations` 版本账本。`003` 与 `004` 是列级迁移，不新增表。
> 本段是冻结时的目标值，**不得用于验收**：2026-11-26 实测当前基线为空库 39 张、MySQL 运行时 40 张、SQLite 41 张，逐项见 §6.1 末的「当前口径（2026-11-26）」与本文件 §8 的「逐表清单」行，以及 `docs/er-v2.md` §1。

### 6.3.1 2026-11-22 扩展：只读投资估值快照

- 来源：生产 pfm 的 `account_stockaccount`、`account_invest`（`status=0` 在持）、`longterm_income_event` 与 `account_ttradesnapshot`。
- 账户：证券账户（按 pfm 券商账户，现金取 `available_cash`）与理财账户（按成员各一个）。
- 收益口径：**当前在持仓位未实现收益 + 已导入股息**；不包含已卖出标的的历史已实现盈亏。
- 上次交易：取 pfm 最近一次交易快照的日期、收益与收益率，只作展示，不重建完整买卖流水。
- 读取：`GET /accounts?include=investments` 投影；不新增业务路由，`TestRouteBudget` 仍为 55。
- 边界：只读；没有投资写入 API、买卖、转账、估值重算或复式分录。

### 6.4 迁移器与基线守卫

- 单一通用迁移器：按嵌入文件名版本升序应用；每个版本记录 checksum；启动时校验版本连续性。
- 版本或 `baseline` 与二进制不符时拒绝启动，不允许自动猜测或跳过。
- 种子数据改为 Go 常量 + `SeedForHousehold`；不再依赖 SQL 种子文件与启动期 `UPDATE`。
- 删除 `db.Migrate` 每次启动执行 `UPDATE categories SET parent_id=NULL` 的副作用；迁移只在版本推进时执行一次。

### 6.5 升级策略

V2 不支持 v1 库原地升级：

- 本地开发：删除 `apps/api/data/tinynest.sqlite3`，由新二进制从零建立 V2 基线。
- 生产：新建库 → 新二进制建基线 → `identity-export` / `identity-import` 迁移 11 张身份表 → 切 `TINYNEST_MYSQL_DATABASE`（详见切换手册）。
- `schema_migrations` 不迁移，由新二进制按 V2 版本重建。
- 加密密钥沿用同一 32 字节文件，否则 SMTP / IMAP 密文不可解。
