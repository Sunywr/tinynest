# TinyNest 高级开发工程师

本技能随 TinyNest 仓库分发。从仓库根目录解析下文路径。先读 `AGENTS.md` 和其中的必读资料，按 [待实施计划](../../../docs/plans/next-implementation-plan.md) 接手未完成工作。

## 从证据确定范围

- 用 Git 核对仓库根目录、当前 SHA、工作树和远端基线。按 `AGENTS.md` 保留已有改动。换机时以实际 checkout 为准，机器路径和工具位置使用当机配置。
- 用路由注册、调用方、数据库迁移和回归测试确认实际功能。读到旧文档里的 `PLANNED` 时，先检查同一能力是否通过其他路径实现。核对账务口径时使用 [决策台账](../../../docs/reviews/v0.1-accounting-decisions.md)，把新的口径选择留给用户确认。
- 从正常入口验证修复。缺陷先写失败测试，记录触发条件，再修复并跑全量回归。异步表单覆盖重复提交、取消后重开与旧响应回填。账务写入覆盖重复请求、事务回滚与余额一致性。

## 评审重点

- 追踪 HTTP 会话权限、SQL 的 `household_id` 条件、事务写入以及 Web 展示。检查整数分、平衡分录、冲正、上海业务日期和幂等，尤其关注在首页或报表聚合时遗漏的隔离条件。
- 涉及持久化时核对本地 SQLite 和生产 MySQL 两种方言及既有数据迁移。涉及页面时沿用 Vue 和奶油团子设计，确认相对 `/api/v1/*` 请求、窄屏操作和真实保存反馈。品牌原图按仓库校验脚本核验。

## 验证与交接

- 使用 [开发说明](../../../docs/DEVELOPMENT.md) 的工具链和隔离数据。记录候选 SHA、命令、通过与失败项。依任务覆盖 Go 测试、vet、tidy、build、前端类型检查、生产构建和浏览器 E2E。环境缺失或无法执行的项目标为 `UNVERIFIED`。
- 发布核对使用 [发布候选复核](../../../docs/reviews/rc-readiness.md) 和 [部署指南](../../../docs/deployment.md)。CI 中的临时库、隔离预发布、生产现场证据各自对应其验证环境。生产部署同时需要用户授权及适用的生产门禁通过。
- 交付时说明实际修改、可复现的测试结果、待确认项和仍缺的验收证据。按用户授权执行提交、推送、合并、打标与部署。
